# 为什么是 16Hz —— 决策原因与设计原则

> 适用范围：决策/采集环（外环）。臂内环 ArmInnerLoop 保持 50Hz 看门狗不变（`inner_loop.py:71`），相机/点云保持 30Hz 不变（`camera_process.py:36`）。HDF5 schema v7，`/meta` 新增 `control_hz`。
>
> 生成方式：2026-07-17 多智能体复查（5 路取证 → 3 路对抗质询 → 综合），所有论断附代码锚点。

## 一、为什么是 16Hz

### 1.1 硬约束（不以意志转移的物理/算力事实）

| 约束 | 事实 | 证据 |
|---|---|---|
| 观测流上限 30Hz | L515 RGB/深度/置信度/IR 全部 30fps，点云在 CameraProcess 子进程同频计算；50Hz 环每秒最多拿到 30 份独立观测，≥40% tick 图像逐字节重复（相机退化到实测 ~17-18Hz 时达 ~65%） | `camera_process.py:36`、`realsense.py:483-493` |
| IK 27ms 基线 vs 20ms 预算 | `solve_teleop_ik` 迭代打满时 15-48ms（基线 27ms = 50Hz 预算的 135%），mplib 兜底尖峰 300-502ms；已实证引发 IK 尖峰→内环 hold→ramp 重置→运动中 C24 急停（2026-07-16），以及慢性超期致相机写入错位累积 20s（ep_211557） | `inner_loop.py:73,304-313` |
| 相机退化态 | L515 中途无声停流/退化史，有效产帧率实测低至 ~17.5Hz；16 < 17.5 < 30，是"每 tick 保证一份新观测"在退化态仍成立的近似最高档（20Hz 则退化期重复率回升 12.5%） | 停流事件记录 |

**更正一处错误前提**：16 的依据不是"≈30/2"（30/2=15），而是"16 < 17.5（退化产帧率）< 30"。16Hz 下重复帧从结构性噪声（50Hz 下每秒必然 20 个 tick 无新帧）变成纯异常信号，`flag_camera_fresh`（0.2s 窗口，`episode_recorder.py:32`）语义变干净。

### 1.2 软约束

- **策略学习惯例**：主流采集档位 10–50Hz。16Hz 紧贴 DROID 15Hz（76k 轨迹、被 OpenVLA/π0 预训练采用），高于 Diffusion Policy 实机 ~10Hz；属"主流偏低"而非离群。VLA 推理端仅 1–6Hz，chunking 解耦采集与部署频率；16 步 chunk @16Hz 覆盖 1.0s 物理时间（50Hz 仅 0.32s）。
- **Mode 6 语义**：固件收到新目标后从当前状态（含速度）在线重规划，稀疏直发可行、无需软件插值（`inner_loop.py:456-465`）；内环 50Hz 重发同一目标对 Mode 6 幂等（最优性原理，固件闭源未实机验证，置信 medium）。
- **数据体积**：相机数据行数降为 50Hz 的 32%，信息量不变（上限都是 30Hz 源）。

### 1.3 逐档否决理由

| 档位 | 否决理由 |
|---|---|
| 50Hz | 27ms IK 基线 = 135% 预算，慢性超期 + C24 链条已实证；40% 观测重复抬高 action\|obs 条件熵 |
| 30Hz | 最强替代（见第四节）——被否决的理由是**时间性的**：不覆盖相机 17.5Hz 退化态；IK 提速后运动期上界与手 NLP 耗时未实测，33.3ms 预算余量是纸面数字。P6 后可一行升档（`vr_teleop_shm.py:68`） |
| 20/25Hz | 两头不靠：不覆盖退化相机（重复率 12.5%/30%），也没拿到 30Hz 的 1:1 相机对齐与生态同频；停走临界 2.2/1.4°/s 仍压在精细带内 |
| 15Hz | 与 16 工程等价（6.7% 数据率差；dt=1/16=0.0625 为二进制精确浮点）；相机与决策环不锁相，整除不带来帧龄均匀 |
| 10Hz | 无本地必要性（预算已宽裕），进一步恶化遥操作手感与停走临界（v*∝T²） |

## 二、设计原则（参数换算审计提炼）

1. **滤波系数按时间常数 τ 不变换算**：`alpha=1−exp(−dt/τ)`。锚点 `signal_utils.py:12-50`；复算 0.6@50Hz→0.9429@16Hz、0.3→0.6720 ✓；与 dex_retargeting LPFilter 的 `y+=α(x−y)` 约定一致。α=1.0（直通）是频率不变量，无需换算（`vr_teleop_shm.py:173-174`）。
2. **速度语义参数按"每秒速率不变"换算**：per-step = 速率/频率。锚点 `vr_teleop_shm.py:70,130`（手 clip deg2rad(90)/16=0.098175 rad ✓ 回程 ×16=90°/s ✓）、`:121`（nullspace 1.0×50/16=3.125°/frame ≙ 50°/s ✓）。
3. **时长语义参数按"秒数不变"换算**：帧数 = 秒×control_hz。max_frames=960(60s)、min_frames=16(1s)、flush=160(10s)、STATUS_EVERY=16(1Hz) 均 ✓。**唯一微偏差**：skip_initial_frames=round(0.2×16)=3 帧=0.1875s，较旧 0.2s 短 12.5ms（舍入，无实质影响）。
4. **秒计超时/看门狗不随决策频率换算**（绑定物理时间或所属设备速率）：`target_timeout_s=0.2`（`inner_loop.py:73`，@16Hz 合 3.2 周期 vs @50Hz 10 周期，绝对陈旧度语义不变）、VR_STALE=0.5s、HOME_DT=0.04s、speed_ramp_frames=20（内环频率未变）。CAMERA_FRESH 0.5→0.2s 是锚定相机 30fps 的**独立收紧**（~6 帧裕度），不是 50→16 派生。
5. **名义栅格率与实测率分离，消费端优先名义率**：start 写 `control_hz=16`（dt 严格 1/control_hz），stop 覆写 fps 为实测值；replay/export 优先 `control_hz`（`episode_recorder.py:206,693`、`replay_traj.py:133-135`）。
6. **调度用绝对期限，超期不追赶**：deadline_k = anchor+k·period，单 tick 抖动不累积；超期≥1 周期重锚定不补发（`rate_manager.py:42,57-84`）。
7. **录制槽位就近取整**：eps=0.5 即四舍五入，容 ±dt/2=±31.25ms 抖动，消除槽界 dup-drop（`episode_recorder.py:191-193`；buffer 库默认 eps=1e-5 未动）。
8. **库默认全部保持 50Hz，16 仅入口点单点定义**：EpisodeRecorder/TeleopControllerConfig/XHandConfig/nullspace 等默认未改；CTRL_HZ=16 仅在 `vr_teleop_shm.py:68` 与 `vr_teleop_arm_only_record_plus.py:155`。

**审计发现的换算陷阱（如实记录）**：
- **手 delta clip 是"再语义化"而非纯换算，构成回退陷阱**：旧默认 0.3 rad/step@50Hz ≙ 859°/s（防尖峰门），新入口按 90°/s 速度语义派生 0.098 rad/send，收紧 ~9.5 倍等效速度。"CTRL_HZ 改回 50"回退会得到 0.031 而非 0.3——完整回退须一并删除 `vr_teleop_shm.py:130` 派生行。
- **过时文档**：CLAUDE.md 中 flag_camera_fresh 仍写 0.5s；`inner_loop.py:76-78` 与 `docs/xarm7-control-loop-2026-07-15.md` 的"0.3 rad ≈10x 余量"按 50Hz 书写，16Hz 下新目标步长 0.098 rad，余量实为 ~3x。

## 三、已知代价与风险边界（诚实清单，关联 P6 验收）

1. **臂侧 1–5°/s 精细速度带落入停走波纹区**（significant）：Mode 6 jerk 主导停走临界 v*=jT²/32（j=500 rad/s³ 固件默认，已独立复算），16Hz→3.5°/s（50Hz 时 0.36°/s）：1–3.5°/s 完全停走（周期内速度触零、峰值≈2×均值）、3.5–5°/s 强波纹。波纹绝对幅度小（~0.22°/周期，EEF 端 0.3–2mm/步）但未实测感知阈值。**→ P6 项：慢速 1–5°/s 段 qvel FFT 查 16Hz 峰**。兜底 `set_joint_jerk`（SDK 1.18.4 有 API）j→50 即恢复 0.35°/s，代价响应全局变软 ~0.16s、重启失效。注意 acc 上界 7.8°/s 对应实配 8.7266 rad/s²（`inner_loop.py:70`），非 20 rad/s²。
2. **手侧 12DOF 无任何缓冲层，16Hz 阶跃直打 P 伺服，未验证**（significant）：`XHand.send_action` 直发无插值（`xhand.py:508-539`），kp=80/ki=0/kd=0，硬件 EMA 默认关闭，重定向 α=0.943 近直通；clip 满格时 5.6°/send。臂侧的全部"稀疏直发无损"论证不覆盖手。**→ P6 应补手侧 qpos/触觉频谱检查**（当前验收只写了臂侧）。修复局部（启用 ema_alpha 或手侧高频重发），不动 16Hz 决策。
3. **手 90°/s 限速削顶快速抓取 + 录制动作被涂抹**（significant）：人类快速捏合可达 300°/s+，clip 后 last_qpos_cmd 回写进 HDF5 action（`controller.py:354-359`），数据集中不存在真实速度分布的抓取。可一行调参放宽，但 16Hz 下"防尖峰门"与"速度限制"两职能被迫耦合在同一个 per-send clip 上——解法是重定向层限速 + 硬件层宽门两级拆分。
4. **16Hz 自录数据对自身波纹结构性失明，不可回溯**（significant）：16/32/48Hz 波纹分量混叠到 DC 且采样与下发相位锁定，qpos 在录制数据里看起来光滑。**→ 顺序约束：P6 必须先于批量采集，验收用外部高频通道（SDK get_servo_angle @100Hz+）**；P6 前采的 episode 事后无法从数据自审波纹。
5. **生产路径 /arm_qvel、/arm_tau 全 NaN**（significant，历史遗留但属迁移错失的必修项）：`interface.py:164-173` 传 arm_qpos 分支置 NaN，validator 刻意不查；内环 50Hz 读到完整 qvel 只存标量丢弃（`inner_loop.py:385-388`）。修复 ~10 行且与频率正交，落地前"录制数据可做力学层诊断"不成立。
6. **相机速率退化被录成正常文件**：16Hz 把 17.5fps 退化态与 30fps 正常态录成完全一样的数据，flag_camera_fresh(0.2s) 只抓完全停流抓不到速率退化——30Hz 栅格下重复率突增反而是退化信号。16Hz 的"0% 重复"优势与"掩盖退化"是同一枚硬币两面。
7. **触觉瞬态欠采样**：tactile 为每 tick 瞬时快照，20ms 冲击被采到概率 ~32%，事件计时量化 ±31ms，三模态时序偏斜最大 ~95ms。当前 10N 阈值抓握判定够用；转向插拔/轻放/滑移补偿类任务时此项升级为硬伤。
8. **遥操作指令陈旧度 +21ms（平均）/+42.5ms（最坏）**：有力反驳成立（真实对照是"退化的 50Hz ~37Hz + 尖峰冻结"，且 Quest 追踪 20-40ms、固件爬升 0.2s 占主导）。
9. **决策归因混淆**：IK 提速（p50 0.53ms）与降频同批落地，两副药治一种病，无法事后归因"16Hz 是否必要"。**→ P6 补测提速后 IK 运动期分布 + 手 NLP 耗时（从未纳入 StageTimer），用数据决定是否升 30Hz**。
10. **mplib 兜底尖峰未被消除**：300–500ms 仍同时击穿 62.5ms 预算与 0.2s 内环超时；16Hz 只把"慢性超期"变"罕见尖峰"，真正的防线是 IK 提速 + ramp 1.25×qvel 下限（`inner_loop.py:484`）+ C24 可恢复化三项正交修复。

## 四、被否决的替代方案

**① 控制 50Hz + 录制 16Hz（解耦）** — 否决。三重理由：(a) 50Hz 控制环本身是事故源，IK 提速后运动期最坏推算 18.5–22.5ms 对 20ms 预算仍边缘；(b) 训练/部署动力学错配：demo 在 50Hz 微动力学（v*=0.36°/s）下执行、部署 16Hz 直发落入 3.5°/s 停走区，违背"训练=部署一致"原则；(c) 隐性坑实锤：`timestamp_buffer.py` docstring 称 fast-source "latest wins"，代码实为 **first-wins**（:62-66 早到样本整帧丢弃）——50Hz 喂 16Hz 栅格会系统性录到每窗口最早动作（滞后至多 ~40ms），"零成本解耦"不成立。

**①′ 全速率录制 + 离线降采** — 否决但承认信息论上严格占优（forward-fill 冗余可逆、16Hz 抽取不可逆）。工程反驳：前提仍是 50Hz 环跑得动；单栅格+单写线程是修完七个对齐 bug 换来的简单性，本项目实证失败模式全是对齐 bug 而非带宽不足。**残余价值应吸收**：ArmInnerLoop 本就 50Hz 读状态，加一条 50Hz 旁路日志即可低成本保留高频运动学（未做，建议排期）。

**② 30Hz 全环** — 最强替代方案，如实说明：与相机 1:1 同频、停走临界降到 1.0°/s、生态同频、提速后 IK 预算推算仅 66%。16Hz 相对它的真实增益只剩"覆盖未修复的相机退化态 + 未实测路径的预算余量"——**均为故障缓冲而非最优设计**。结论：16Hz 是当前（L515 停流未根治、IK 提速上界未实测）的保守正确选点；P6 通过且相机退化解决后，升 30Hz 是 `vr_teleop_shm.py:68` 一行改动，且 16Hz 旧数据可与新数据混训。

**③ 20/25Hz 折中** — 否决。频率选择的合理结构是两个极点二选一（16 保守覆盖故障态 / 30 相机同频最优），中间档把两边缺点各取一半而无任一维度最优。
