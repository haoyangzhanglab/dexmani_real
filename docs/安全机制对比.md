# 参考项目安全机制审计

> **审计对象**：ManiUniCon · LeFranX · Dexora · lerobot_ufactory · PF-DAG · pi-r2-flow
>
> 审计六个桌面参考机器人项目在**运行时控制路径**上的安全机制，作为 DexMani Real 后续简化/借鉴决策
> 的参考。§0–§5 仅覆盖六个外部项目；§6 在该审计基础上核对 DexMani Real 当前机制，并给出面向有人值守、
> 低速、固定工位实验室场景的简化边界。
>
> 生成日期：2026-08-13。各项目源码反映各自 2026-08-13 检出的工作树状态；未做任何硬件执行。

---

## 导读（TL;DR）

**一句话结论**：LeFranX 是六者中**软件安全最强**（Ruckig 硬限 + 0.5 s 命令 stale 看门狗 + 显式碰撞
阈值）；**PF-DAG 与 pi-r2-flow 是最危险的研究原型**——前者主动关闭固件碰撞检测 + 无界自动 re-arm，
后者的 `clip_to_state`/`apply_ema` 是死代码、`raw_action` 直发；Dexora 与 lerobot 介于中间、各有明显
缺口。

**六个项目的共同缺口**：无 ARMED/DISARMED/FAULT 状态机、无硬件急停接线、无软件碰撞检测。

**方法**：固定 13 个安全维度逐项目判定；只判运行时控制路径（死配置单独标注为「声明但未生效」）；
所有 `path:line` 与数值均已对源码核实。

### 0.2 分类法（固定 13 类）

判定对象是**运行时控制路径**（遥操作 / 部署 / forwarder / 服务器），而非离线训练或死代码——
后者单独标注为「声明但未生效（死代码）」。

1. 状态机（ARMED/DISARMED/RUNNING/FAULT 及转移归属）
2. 关节/位置/速度/加速度/力矩限位（数值 + 强制方式）
3. 工作空间 / Cartesian 边界
4. 碰撞检测（软件 vs 固件）
5. 急停 / e-stop / 制动 / 急停开关
6. 错误与故障处理（检测 / 粘滞 / clear_error / 恢复）
7. 发送前命令校验门（reject vs clip，是否静默）
8. 看门狗 / 心跳 / 进程监督（含命令流 staleness）
9. 回零 / 返航安全
10. XHand 安全（力矩/电流/接触/命令边界/总线保护）
11. VR 遥操作安全（retargeting/mapping 边界、dead-man）
12. 策略部署安全（preflight / 动作 clamp / 平滑）
13. 配置阈值清单（哪些字段真实生效 vs 死代码）

## 1. 项目快照

### 1.1 ManiUniCon
多进程（`torch.multiprocessing` + 共享内存）通用控制框架，三种模式——遥操作/采集（Quest VR、
SpaceMouse、键盘、Gello）、策略推理（TorchModelPolicy / VLA）、回放——运行于 UR5（RTDE）、
XArm6、Franka FR3（franky）、Franka Panda（deoxys，已废弃）或 Meshcat 仿真器。**本仓库无 XHand**，
仅有平行夹爪（Franka hand / Robotiq）。

**安全理念**：无中心状态机，靠共享布尔标志（`is_running` / `is_recording` / `error_state`）+
每接口错误标志 + 每动作原地 clip；软件碰撞检测缺失，固件兜底。

### 1.2 LeFranX
LeRobot 扩展，通过 Quest VR retargeting 遥操作并部署 Franka FER 7-DoF + XHand 12-DoF。安全核心
是一个 **C++ 实时服务器**（`franka_server.cpp`），把网络位置目标经 **Ruckig** 平滑为 1 kHz 速度
命令，碰撞反射与阻抗委托给 **libfranka 固件**。Python 层（`src/lerobot/…`、`scripts/…`）补充相对
动作 clamp、手部关节/力矩限、VR 工作空间 clamp 与急停接线。

**安全理念**：固件 + C++ Ruckig 实时边界；软件层在这六个项目中**最强**（命令 stale 看门狗、
硬性速度/加速度/jerk 限、碰撞阈值显式配置）。

### 1.3 Dexora
ICRA-2026 双臂双手 36-DoF VLA。运行时为 3 进程 ZMQ 拆分：`dexora_inference_zmq.py`（策略主机）
→ `mmk_forwarder.py`（双臂，:5556）与 `xhand_forwarder.py`（双手，:5557）。遥操作用 Vision-Pro
retargeting + AIRBOT “imitate-all” 采集。

**安全理念**：极薄 forwarder，安全几乎全部 = 两个 forwarder 里的**关节位置 clip** + XHand RS485
**总线保护**（CRC 重试/节流）。无状态机、无 e-stop、无运行时碰撞/力矩守卫。

### 1.4 lerobot_ufactory
LeRobot（`lerobot==0.4.3`）插件，接入 UFACTORY xArm 臂 + 夹爪（xArmGripper / G2 / BioGripper /
Pika / Robotiq 2F-85），遥操作为 GELLO / Pika / UMI / SpaceMouse。`uf_robot` 包包装 `xarm-python-sdk`
`XArmAPI`，实现 LeRobot `Robot` 接口。

**安全理念**：**纯固件委托**（`motion_enable` / `set_mode` / `set_state` / `clean_error` / error-code
检查），软件侧极薄——仅速度上限、调试用 `no_action` 开关、少量夹爪 clamp 与键盘 ESC。

### 1.5 PF-DAG
ICLR-2026 两阶段模仿学习（Primary Mode Policy + Mode-Conditioned MeanFlow），遥操作/部署栈为
xArm7 + XHand（Quest）或 xArm7 + 夹爪（GELLO）。README 明言“very raw, runnability NOT verified,
policies not fully deployed”。

**安全理念**：**研究原型 / 作者自认未验证**。唯一真实强制 = 底层线程的 **L2 关节增量 clamp**；
**主动关闭 xArm 固件碰撞检测**（`set_collision_sensitivity(0)`）；其余安全层（dead-man、看门狗、
速度/加速度限、粘滞 fault）在中文指南里逐条列为 P0 缺失项。

### 1.6 pi-r2-flow
PI-R2（Reactive Real-time Flow Policies）部署栈，xArm6 + XHand + GR00T VLA，约 25 Hz 控制环，把
18 维流策略动作块流式发给位置伺服 xArm（mode=1）与 RS485 XHand。`learning/Isaac-GR00T` 是训练侧
（NVIDIA fork 子模块，未检出）。

**安全理念**：**纯固件委托 + 软件安全原语为死代码**。固件侧有碰撞灵敏度（2）+ jerk（100）/maxacc
（20）+ XHand `tor_max=300`；软件侧两个本应做动作 clamp/平滑的 `clip_to_state` / `apply_ema`
**定义但从未 import/调用**，`action = raw_action` 直发。中文技术报告把「软件安全包络」列为头号 P0。

## 2. 分类对比

> 每小节依次列出各项目做法（`path:line` 均为已核对源码的引用），末尾给出交叉对比结论。

### 2.1 状态机（ARMED/DISARMED/RUNNING/FAULT）

- **ManiUniCon** `ABSENT` — `utils/shared_memory/shared_storage.py:179-183` 三个
  `multiprocessing.Value` 标志 `is_running` / `is_recording` / `error_state`；`error_state`
  **粘滞**，一旦置位所有循环 `break`，无自动 clear（恢复 = 重启进程树）；`robot_ready` /
  `policy_ready` `Event` 实现两段握手（`:192-196`）。
- **LeFranX** `ABSENT`（固件持有）— C++ 服务器 `franka_server.cpp:49-51` 原子布尔
  `running_` / `client_connected_`；真实状态机在 libfranka `control()` / `MotionFinished`；Python
  侧 `_is_connected` 仅镜像连接标志。
- **Dexora** `ABSENT` — 无 ARMED/DISARMED/FAULT；`airbot_com_mmk2.py:103-105`
  `enter_active_mode` / `enter_passive_mode` 仅存字符串、无行为；`enter_traj/servo_mode`
  只切换控制模式而非安全状态。
- **lerobot_ufactory** `ABSENT` — 靠 xArm 固件 `set_mode`/`set_state` + LeRobot
  connect/configure 生命周期（`uf_robot.py:212-215, 261-268, 423-424`）。
- **PF-DAG** `ABSENT` — 最接近的是 `XArmXHandEnv.step` 里 `self.control` 布尔门（`env.py:172-203`），
  键盘切换而非安全事件；期望状态机仅存在于中文指南（`PF-DAG_真机实验与代码实现指南.md` mermaid
  Idle→Armed→…）未实现。
- **pi-r2-flow** `ABSENT` — 仅 `run_policy.py:416-422` 一个 SIGINT 置位的 `stop` 布尔；期望的
  `HOMING→WARMSTART→RAMP→RESEED→RUNNING` 状态机（含 RUNNING→HOLD/STOP 转移）仅在技术报告 mermaid
  中，未实现。

**结论**：六项目**无一**实现真正的 ARMED/DISARMED/RUNNING/FAULT 状态机；最多是共享布尔标志或直接
操纵固件 mode/state。ManiUniCon 的粘滞 `error_state` 是最接近「故障锁存」的机制，但无恢复回路。

### 2.2 关节/位置/速度/加速度/力矩限位

- **ManiUniCon** `CLIP` — `robot_interface/base.py:89-113` `validate_action()` 原地
  `np.clip` 关节位置/速度/力矩到 yaml 边界但**恒返回 `True`**（`:113`，永不拒绝）；硬编码值：
  XArm6 `xarm6.yaml:10-14`（velocity 3.14 rad/s、torque 150 Nm）、UR5/Panda/FR3 各自 yaml；
  FR3 每步 0.6 rad delta clamp + 0.005 deadband（`franka_fr3_franky.py:407-434`）；`utils/filter.py`
  `JointSpaceSmoother` 默认速度 2.0 / 加速度 5.0；Ruckig `ruckig_utils.py:14` max_velocity
  80°/140°；IK 侧 `ik_solver.py:126-141` pink `ConfigurationLimit` + `VelocityLimit`。
- **LeFranX** `HARD` — C++ `franka_server.cpp:80-82` 每关节 `MAX_JOINT_VELOCITY
  {1.5,1.5,1.8,1.8,2.0,2.0,2.0}` rad/s、`MAX_JOINT_ACCELERATION {4,4,4,4,6,6,6}` rad/s²、
  `MAX_JOINT_JERK {8,8,8,8,12,12,12}` rad/s³，装入 Ruckig（`:94-98`）；输入关节位置 `abs>3.0`
  仅**警告**不拒绝（`:226`）；IK `weighted_ik.cpp` 只对 **q7** 硬限（q1–q6 越界只要非 NaN 即接受）。
- **Dexora** `CLIP` — 双臂 6 关节 `np.clip`（`mmk_forwarder.py:106-134`，越界仅警告仍发送）；双手
  12 关节 `JOINT_LIMITS_RAD` clip（`xhand_forwarder.py:81-124`）；**无速度/加速度/力矩限**。
- **lerobot_ufactory** `PARTIAL` — `uf_robot_config.py:22-23` `max_joint_velocity=90` °/s、
  `max_linear_velocity=200` mm/s；前 20 命令用 0.2 rad/s 慢同步（`uf_robot.py:19,351-352`）；
  `set_linear_spd_limit_factor(2.0)`（`:207`）；**无加速度/力矩限**。
- **PF-DAG** `CLIP`（仅 L2 增量）— xArm 每步 L2 增量 clamp `DEFAULT_MAX_DELTA=0.05` rad
  （`xarm_robot.py:123, 260-261`）；XHand `DEFAULT_MAX_DELTA=0.5` rad（`xhand_robot.py:110, 354-355`）；
  **无每关节速度/加速度/力矩限**；`joint_velocities` 实为 `joint_positions`
  （`xarm_robot.py:337`，任何下游速度检查读到的是位置）。
- **pi-r2-flow** `PARTIAL`（固件）— 固件 jerk `--joint-jerk=100` rad/s³、maxacc `--joint-maxacc=20`
  rad/s²（`_policy_args.py:29-34` → `xarm_sdk.py:89-94`）；**无速度限、无每关节位置 hard limit、无
  软件 delta clamp**（`clip_to_state` 为死代码，见 §2.12）。

**结论**：LeFranX 是唯一在**软件层硬性强制**速度/加速度/jerk 上限的；pi-r2-flow 只靠固件 jerk/maxacc；
PF-DAG 只有 L2 增量 clamp 且无任何每关节速度限；Dexora/lerobot 力矩限缺失。

### 2.3 工作空间 / Cartesian 边界

- **ManiUniCon** `PARTIAL` — `workspace_bounds` schema 在每个 robot yaml，`core/robot.py:72-172`
  与各 policy 双重 clip；但真实机器人默认全 `null`（仅 Panda 填值），默认不生效。
- **LeFranX** `HARD`（VR 侧）— `arm_ik_processor.py:230-232` 0.75 m 球 clamp；
  `config_franka_fer_vr.py:33` `max_position_offset=0.75`。
- **Dexora** `ABSENT` — 运行时无 Cartesian 边界（仅离线训练 config + KDL 库 spine 断言）。
- **lerobot_ufactory** `ABSENT` — 无 Cartesian box / `set_reduced_mode`（仅 mock 脚本与注释掉的 z-min）。
- **PF-DAG** `PARTIAL` — Quest IK 目标 clip 到 `scene_box`（`quest_agent_xhand.py:174`；
  `constants.py:16-20` x∈[0.15,0.7] y∈[-0.4,0.4] z∈[0.2,0.7] m）；`table_top_box` 仅点云裁剪非运动界；
  真实部署路径无关节位置界（关节 `np.clip` 只在 PyBullet 仿真 demo 里）。
- **pi-r2-flow** `ABSENT` — 无 Cartesian/工作空间/末端位姿监控，无 `set_boundary`。

**结论**：仅 LeFranX（0.75 m）、ManiUniCon（需填值）、PF-DAG（Quest 侧 scene_box）有部分边界；
pi-r2-flow 与 Dexora/lerobot 完全缺失。

### 2.4 碰撞检测（软件 vs 固件）

- **ManiUniCon** `ABSENT`（软件）— `collision_model=None`（`ik_solver.py:94`），纯靠固件。
- **LeFranX** `FW+HARD` — `franka_server.cpp:372-378` `setCollisionBehavior` 关节力矩
  `{250,250,250,250,200,200,150}` N·m + Cartesian 力 `{150×6}`；关节阻抗
  `setJointImpedance {3000,3000,3000,2500,2500,2000,2000}`（`:379`）；更保守 `setDefaultBehavior`
  从未调用。
- **Dexora** `ABSENT`（运行）— 仅离线回放过滤（加速度尖峰 6σ 标记 `collision_free`）。
- **lerobot_ufactory** `ABSENT` — 无 `set_collision_sensitivity` 等调用。
- **PF-DAG** `ABSENT`（且主动关闭）— `set_collision_sensitivity(0)`（`xarm_robot.py:206`、
  `xarm_robot_wo_gripper.py:191`）**关闭固件碰撞检测**，且该例程在 init 与每次错误重试循环中执行，
  故实际长期处于关闭态；无软件碰撞检测。
- **pi-r2-flow** `FW` — `set_collision_sensitivity`（CLI 默认 `2`，`_policy_args.py:27-28` →
  `xarm_sdk.py:86`；构造函数默认 `4` 与 CLI `2` 不一致）；运行时**从不 poll 或反应**碰撞事件/error_code。

**结论**：LeFranX 唯一显式配置碰撞阈值；pi-r2-flow 有碰撞灵敏度但运行时无反应；**PF-DAG 主动关闭
固件碰撞检测**，是六项目中最危险的一项（作者指南 P0 明确要求恢复）。

### 2.5 急停 / e-stop / 制动 / 急停开关

- **ManiUniCon** `STUB/PARTIAL` — 键盘 Space=`_emergency_stop` 仅 hold 不触发硬件；**FR3 `stop()`
  空实现**（`franka_fr3_franky.py:335-344`）；XArm6 `stop()` 真调 `emergency_stop()`。
- **LeFranX** `PARTIAL` — 网络 `STOP` 覆盖为当前关节软停；客户端断开→hold；control 结束
  `robot_->stop()` 硬件制动；**XHand `stop()` 空 stub**（`xhand.py:371-378`）。
- **Dexora** `ABSENT` — 仅 `inference.sh` trap kill 进程、ESC、SIGINT 递归 terminate。
- **lerobot_ufactory** `PARTIAL` — ESC；`disconnect()` `set_state(4)`；`no_action=True` 软 kill；
  teleop enable 门关断冻结。
- **PF-DAG** `ABSENT` — 无 `estop`/`emergency_stop`/`set_pause`/`set_servo_detach`；`stop()` 仅
  `running=False`+`disconnect()`+`join`（`xarm_robot.py:144-150` 等），**不 `motion_enable(False)`、
  不 servo detach、不释放夹爪**，且控制循环从不调用它；`scripts/kill_robot_node.py` 是进程杀手
  （SIGKILL），杀进程后 xArm 仍在 servo 模式执行最后目标直到固件自停。
- **pi-r2-flow** `PARTIAL` — 断开时 `set_state(3)`（`xarm_sdk.py:104`）+ 手部 passive（`xhand_robot.py:146-154`）；
  Ctrl-C→`finally` disconnect；无 SIGTERM 处理、无物理急停接线、无 estop 轮询。

**结论**：六项目无一有真正的硬件急停接线；PF-DAG 的 `stop()` 最不安全（断开不制动）。多个项目的
`stop()` 是空实现或 stub（ManiUniCon FR3、LeFranX XHand），复合机器人急停只真正停到臂或手之一。

### 2.6 错误与故障处理（检测 / 粘滞 / clear_error / 恢复）

- **ManiUniCon** `PARTIAL` — 共享 `error_state` 粘滞；**FR3 `clear_error()` 引用不存在的
  `self.robot_c` → AttributeError**（`franka_fr3_franky.py:327-328`）；`clear_error` 未接线到 main。
- **LeFranX** `PARTIAL` — Ruckig 非 Working/Finished → 全速度置 0；`ControlException`→`stop()`；
  **XHand recover 是 stub**（`xhand.py:380-387`）。
- **Dexora** `PARTIAL` — arm/hand forwarder try/except 返回 error；hand **CRC 重试+退避**；5 s ZMQ
  RCVTIMEO；无粘滞 fault/clear_error。
- **lerobot_ufactory** `PARTIAL` — configure 时 `clean_error()`+`get_err_warn_code()` 非零 raise；
  **发送时 `if error_code != 0: return action` 静默丢弃**（`uf_robot.py:343-344`）。
- **PF-DAG** `PARTIAL`（危险）— 所有 xArm 错误走 `_clear_error_states` 自动恢复
  （`clean_error→motion_enable→set_collision_sensitivity(0)→set_state(0)`，`xarm_robot.py:197-215`）；
  **无界重试循环** `while code != 0: _clear_error_states()`（`:221, 298-307`）无上限、无人工确认、
  每次重试重新使能运动并回 READY；**从不调用 `get_err_warn_code`**（盲清不查）；无 FAULT 锁存
  （指南明言禁止此模式）。
- **pi-r2-flow** `PARTIAL` — 连接时 3 次恢复（`clean_error→motion_enable→set_mode(0)→set_state(0)`，
  `xarm_sdk.py:61-82`）；**观测返回 None 不 halt 循环**（`run_policy.py:1008-1013` 仍 send_action）；
  臂 `set_servo_angle_j` 返回码**忽略**（`xarm_sdk.py:146`）；无 runtime clean_error/粘滞 fault。

**结论**：PF-DAG 的**无界自动 re-arm 循环**是危险反模式（盲清+重新使能）；pi-r2-flow 观测失败仍继续
发送、返回码忽略。四者（ManiUniCon/LeFranX/Dexora/lerobot）各有明确故障处理但均无自动恢复回路。

### 2.7 发送前命令校验门（reject vs clip）

- **ManiUniCon** `CLIP` — `core/robot.py:348-358` 时间戳门 + workspace clip + `validate_action()`
  （恒 True）。
- **LeFranX** `HARD` — `SET_POSITION` 精确 7 浮点（`franka_server.cpp:215-244`）；Python
  `max_relative_target` clamp（`franka_fer.py:246-255`）默认 None 未启用。
- **Dexora** `CLIP` — arm 维度(12)→joint clip→追加固定 head/spine；hand `_clamp_hand_action`；
  **ZMQ 无鉴权**；无 dead-man/armed 门。
- **lerobot_ufactory** `ABSENT` — 发送前无数值校验（仅夹爪位置 clamp）。
- **PF-DAG** `CLIP/维度` — `RobotEnv.step` 断言长度（`env.py:52-55`）；但 `XArmXHandEnv.step`
  **盲切** `joints[:7]`/`joints[7:]`（`env.py:188-189`）无长度校验；Dynamixel 力矩门
  （`dynamixel/driver.py:216-217`）；**无 NaN/finite/范围校验**（NaN 策略输出直入 `set_servo_angle_j`）。
- **pi-r2-flow** `仅形状` — 臂/手 shape 校验（`xarm_sdk.py:142-143`、`xhand_robot.py:195-198`）；
  `to_absolute` 仅 delta→绝对加法、无 clamp（`control_utils.py:104-114`）；`action = raw_action`
  （`run_policy.py:999`）；**无 NaN/joint/delta/velocity 校验**。

**结论**：全部是「clip 后照发」或仅形状校验；**无一**在发送前做 NaN/finite/范围检查。pi-r2-flow 与
lerobot 最弱（几乎零校验门）。

### 2.8 看门狗 / 心跳 / 进程监督（含命令流 staleness）

- **ManiUniCon** `ABSENT` — 无心跳/进程监督；仅 Ruckig 命令流 stale hold（`use_ruckig=false` 不生效）；
  main 仅 `sleep(0.1)` 轮询。
- **LeFranX** `HARD` — 命令 stale watchdog `COMMAND_TIMEOUT_SEC=0.5`（`franka_server.cpp:58,358-361`）
  stale→hold；VR 消息 stale `message_timeout_ms` 失效→hold。
- **Dexora** `PARTIAL` — 5 s ZMQ 超时只 raise 进 finally 关 socket、**不触发安全停**；无运行时心跳。
- **lerobot_ufactory** `ABSENT` — 无心跳/监督；RT report 线程保证状态新鲜但无安全动作。
- **PF-DAG** `ABSENT` — ZMQ server `RCVTIMEO=1000 ms` 仅打印不停止（`robot_node.py:32,59-61`）；
  **client 无 RCVTIMEO 阻塞**（`robot_node.py:71-125`）；无心跳/时间戳/staleness 检查。
- **pi-r2-flow** `ABSENT` — ZMQ 60 s per-request 超时（`groot_client.py:89-90`）；无命令流 staleness
  watchdog（GR00T worker 停止→“hold last action” 无限）；worker 新鲜度用时间戳相等而非单调序号
  （`run_policy.py:739-745`）；无心跳/keepalive。

**结论**：LeFranX 0.5 s stale watchdog 是唯一真正 “stale → hold” 的安全看门狗；其余五项目无命令流
staleness 保护，最坏情况是「策略/服务器死 → 臂保持最后目标」。

### 2.9 回零 / 返航安全

- **ManiUniCon** `PARTIAL` — `h` 键 `reset_event` 排空队列后各接口 `reset_to_init()`。
- **LeFranX** `HARD` — `home_position`；`reset_to_home()` 重连+`MOVE_TO_START`，server
  `MotionGenerator(0.5, …)` 半速梯形（`franka_server.cpp:591-603`）。
- **Dexora** `PARTIAL` — `default_action` + SDK `reset`；XHand 上电回固定位；无碰撞自由轨迹。
- **lerobot_ufactory** `PARTIAL` — `start_joints` 慢速阻塞移动；`calibrate()` no-op、`is_calibrated()`
  恒 True。
- **PF-DAG** `PARTIAL` — `np.linspace` 插值回 `reset_joints`（`run_env.py:143-150`），每步仍过 0.05
  clamp 但**无轨迹校验**（无关节限/自碰撞检查）；无 homing 例程、无故障返航、断开不归位。
- **pi-r2-flow** `PARTIAL` — `interpolate_to` 150 步 @25Hz ≈6 s（`control_utils.py:29-56` →
  `run_policy.py:253-255`）；`--no-home` 可跳过；**退出不 return-home**（`finally` 只 disconnect）。

**结论**：LeFranX 回零最稳健（半速梯形、独立会话）；pi-r2-flow/PF-DAG 有插值但无碰撞自由轨迹校验，
且退出不归位。

### 2.10 XHand 安全（力矩/电流/接触/命令边界/总线保护）

- **ManiUniCon** `ABSENT` — 无 XHand（仅平行夹爪 20 N）。
- **LeFranX** `PARTIAL` — 12 关节限位 clip（`xhand_config.py:44-60` → `xhand.py:288-297`）；
  `default_tor_max=400` mA（`xhand.py:111`）；`max_torque=300` 死字段；stop/recover 为 stub。
- **Dexora** `PARTIAL` — 关节 clip + NaN 清洗 + **RS485 总线保护**（0.12 s 节流 + CRC 重试 +
  `write_timeout=0.05`）；无力/力矩/温度检查。
- **lerobot_ufactory** `ABSENT` — 无 XHand（仅夹爪）。
- **PF-DAG** `PARTIAL` — `DEFAULT_TOR_MAX=380` / `DEFAULT_KP=120`（`xhand_robot.py:105-109, 233-240`，
  作者指南标「激进」）；**指尖力读取但从不用于安全**（`xhand_robot.py:277-296`，无接触/过载阈值/自动
  释放）；无电流/温度/总线健康监控；每步 0.5 rad L2 clamp 是唯一运动限。
- **pi-r2-flow** `PARTIAL` — `tor_max=300`（`xhand_robot.py:46,140`）、`kp=100`（`:43`）；
  RS485 线程锁（`threading.Lock()`，`:63`）；**传感器零位带接触检查**（`reset_sensors(verify=True,
  verify_thresh_n=2.0 N)`，`:252-326`）；`joint_torques`/`fingertip_force`/`joint_temperatures`
  读取但**从不阈值检查**；无手部位置命令边界。

**结论**：Dexora 的 RS485 总线保护与 pi-r2-flow 的带接触检查传感器零位是亮点；但四含 XHand 项目
（LeFranX/PF-DAG/pi-r2-flow/Dexora）**无一**做力/力矩/温度闭环安全，PF-DAG 更以高力矩/高增益默认值
（380/120）运行且读力不用。

### 2.11 VR 遥操作安全（retargeting/mapping 边界、dead-man）

- **ManiUniCon** `HARD` — `quest_controller.py` delta 限幅（pos 0.5→0.1 m、rot 1.0→0.5 rad）超限
  缩放/hold；右手握键门控 `movement_enabled`。
- **LeFranX** `HARD` — 首帧不跳变（`arm_ik_processor.py:117-124`）；IK 失败/异常→hold（`:162-178`）；
  指数平滑 0.7；q7 限；XHand retarget 失败→open-hand 安全回退。
- **Dexora** `ABSENT/薄` — Vision-Pro retargeting 直发不经 `_clamp_hand_action`
  （`receive_from_vision_pro.py:136`）。
- **lerobot_ufactory** `PARTIAL` — Pika/UMI `_teleop_enabled` 冻结+重锚；UMI 夹爪未 clamp 到 [0,1]。
- **PF-DAG** `PARTIAL（dead-man 死代码）` — Quest `detect_control_gesture` 计算 `control_state`
  （`quest_agent_xhand.py:144`）但 `act()` **丢弃它**（`:182` 显式注释掉 `# , self.control_state`）；
  实际门控是键盘 T 键 toggle 而非 hold-to-run；**无跟踪丢失处理**（landmark 无置信度/有效检查）；无
  IK 失败处理（`ikpy` 结果直接返回，失败时继续发上一方向目标）。
- **pi-r2-flow** `N/A`（无遥操作）— 唯一人工门是启动期 `wait_for_key`（`run_policy.py:340-347`），
  仅启动 dead-man、非运行时。

**结论**：ManiUniCon/LeFranX 的 VR 侧有实打实 delta 限幅+失效保持+门控；PF-DAG 的 Quest dead-man
**计算但不接线**（键盘 toggle 代替）；Dexora 直发不 clamp；pi-r2-flow 无遥操作代码。

### 2.12 策略部署安全（preflight / 动作 clamp / 平滑）

- **ManiUniCon** `PARTIAL` — TorchModelPolicy 无自身 clamp，靠机器人侧 workspace+validate+插值限速；
  无 preflight magnitude clamp。
- **LeFranX** `PARTIAL` — `ACTION_SCALE=1.0`+指数平滑 `SMOOTHING_ALPHA=0.5`；回零+2 s；`finally`
  `stop()`+`disconnect()`；无 preflight action clamp（靠 arm 侧默认关）。
- **Dexora** `PARTIAL` — 动作 clamp 委托 forwarder；**rate-limiting 等配置死代码**；有连通性 probe+
  “Press Enter” 门。
- **lerobot_ufactory** `ABSENT/disabled` — eval 无 preflight clamp；`SMOOTH_THRESHOLD=0` 使 clamp 禁用；
  z-min 注释掉；`max_relative_target` 未实现。
- **PF-DAG** `PARTIAL` — 无 preflight（`run_env.py` 直接进控制循环）；**无 NaN/clamp**（`PolicyAgent.act`
  返回原始网络输出）；滑动窗口平滑**注释掉**（`policy_agent.py:200-201`）；action-chunk 重放**不可中断**
  （一旦缓冲，逐 step 弹出、无视观测失效）。
- **pi-r2-flow** `PARTIAL（死代码）` — **`clip_to_state`（`control_utils.py:78-101`）与 `apply_ema`
  （`:146-178`）定义但从未 import/调用**，`action = raw_action`（`run_policy.py:999`）直发；ensemble
  真实生效；preflight arg 校验 + dry-run 真实；**无 NaN/Inf 门、无动作 clamp**。

**结论**：**pi-r2-flow 与 PF-DAG 各自的本应做动作安全过滤的原语要么是死代码（clip_to_state/apply_ema）
要么被注释（PF-DAG 滑动窗口平滑）**——两者都直接把原始策略输出发给伺服。Dexora 把 clamp 放在
forwarder 最诚实但 knobs 死代码；lerobot 全禁用。

### 2.13 配置阈值清单（真实生效 vs 死代码）

- **ManiUniCon** — 生效：`joint_limits`（位置 clip）、`max_pos_speed`/`max_rot_speed`、quest delta 限；
  疑似失效：`velocity_limits`/`torque_limits` 在 FR3/XArm6/Panda yaml 中均为 `[列表]` 而非 `{min/max}`
  dict（`joint_limits` 才是 dict），`validate_action` 却以 `["min"]/["max"]` 索引 → 速度/力矩 clip 分支
  若被触达即抛 TypeError（位置控制下潜伏）；FR3 的列表更只有 6 元素对 7-DoF；`workspace_bounds` 默认
  null。
- **LeFranX** — 生效：C++ 硬编码 vel/accel/jerk、碰撞阈值、阻抗、命令超时；`default_tor_max=400`、12
  关节限；死字段：`max_torque=300`、`action_timeout`、`check_arm_hand_collision`。
- **Dexora** — 生效：`control_frequency=20`、`xhand_min_send_interval_s`、retries/backoff、关节常量；
  死代码：`use_rate_limiting` 等整套 rate-limiting。
- **lerobot_ufactory** — 生效：`max_joint_velocity=90`/`max_linear_velocity=200`、`no_action`；
  其余 yaml `max_linear_velocity`/`max_value`/`start_joints`。
- **PF-DAG** — 生效（硬编码）：`max_delta` 0.05/0.5、`DEFAULT_TOR_MAX=380`、`DEFAULT_KP=120`、
  `scene_box`；死：`DEFAULT_MAX_JOINT_DELTA=1.0`（仅未调用 helper 用）、`move_to_start_position`、
  `control_state`（dead-man）、注释的滑动窗口平滑、指南里的 `SafetySupervisor` 样例（非仓库）。
- **pi-r2-flow** — 生效：CLI `--collision-sensitivity 2`/`--joint-jerk 100`/`--joint-maxacc 20`、
  `--ensemble`、`--rate-hz 25`；硬编码不暴露：XHand `tor_max=300`/`kp=100`；死代码：`clip_to_state`/
  `apply_ema`（无 CLI、未调用）；不一致：xArm `collision_sensitivity` 构造函数 `4` vs CLI `2`。

**结论**：六项目都有「声明但未实现」的安全阈值，Dexora 最严重（整套 rate-limiting 死代码），
pi-r2-flow/PF-DAG 的本应做动作过滤的原语是死代码或注释。评估任何外部项目「安全配置」必须 grep 消费点。

3. Quest dead-man 是死代码（`quest_agent_xhand.py:182` 注释掉 `control_state`），实际键盘 toggle。
4. `stop()` 不制动（无 `motion_enable(False)`/servo detach/释放夹爪），且控制循环不调用它。
5. `joint_velocities = joint_positions`（`xarm_robot.py:337`）。
6. 无 NaN/范围校验；`XArmXHandEnv.step` 盲切无长度校验。
7. ZMQ client 无 RCVTIMEO 阻塞，server 超时仅打印；无看门狗。
8. XHand `TOR_MAX=380`/`KP=120` 高默认值 + 指尖力读而不用。

### 4.6 pi-r2-flow
1. **`clip_to_state`/`apply_ema` 死代码**（`control_utils.py:78-101,146-178` 定义但从未 import），
   `action = raw_action`（`run_policy.py:999`）。
2. 无 NaN/Inf 门、无软件 delta/joint clamp、无速度限。
3. 臂 `set_servo_angle_j` 返回码忽略（`xarm_sdk.py:146`）；观测 None 仍继续发送（`run_policy.py:1008-1013`）。
4. 无运行时 watchdog/HOLD（GR00T 死 → 无限 hold last action）；worker 新鲜度用时间戳相等而非单调序号。
5. 退出不 return-home；XHand torque/force/temp 读取但从不阈值检查。
6. xArm `collision_sensitivity` 构造函数 `4` vs CLI `2` 不一致。

## 5. 跨项目模式与结论

### 5.1 三条横切模式

**模式 A — 固件委托 vs 软件门的分工。** 六项目无一例外把「最后一道」安全交给固件（xArm Mode 6 /
libfranka 碰撞反射 / airbot 固件 / xArm 碰撞灵敏度 + jerk/maxacc）。差异在软件层补了多少：LeFranX 在
C++ 实时层补了 Ruckig 硬限 + 命令 stale 看门狗；ManiUniCon 补了共享 `error_state` + 原地 clip；
lerobot 几乎不补（仅 error_code 拦截）；Dexora 补了关节 clip + 总线保护；**PF-DAG 与 pi-r2-flow
几乎不补，且各自的「软件安全层」要么是死代码、要么被注释**。

**模式 B — silent-clip vs reject-and-hold。** 绝大多数「校验门」是**静默截断后照发**或仅形状校验
（ManiUniCon `validate_action` 恒 True、Dexora 关节 clip、pi-r2-flow 仅 shape）。真正 “reject/hold”
的只有 LeFranX 的格式校验 + 命令 stale hold，以及 ManiUniCon/LeFranX 的 VR 失效保持。

**模式 C — 每个项目唯一真正稳健的机制。** LeFranX 的 **0.5 s 命令 stale watchdog + Ruckig 硬限**；
Dexora 的 **XHand RS485 总线保护**（CRC 重试 + 节流）；lerobot 的 **error_code 发送前拦截**；
ManiUniCon 的 **粘滞 `error_state` 跨进程广播**；PF-DAG 的 **L2 关节增量 clamp**（唯一真实运动限，
但固件碰撞被其关闭）；pi-r2-flow 的 **XHand 带接触检查传感器零位 + RS485 线程锁**（但动作过滤是死代码）。

### 5.2 总体观察

这些参考项目在「机器人运行安全」上普遍比其在数据/训练侧的工程量要薄，且「安全配置」中存在大量
**声明但未实现**的死字段——评估时必须核对消费点而非只看 YAML。**PF-DAG 与 pi-r2-flow 两个研究原型
尤其危险**：前者主动关闭固件碰撞检测 + 无界自动 re-arm，后者的软件安全原语（clip/ema）全是死代码、
原始策略输出直发伺服；两者作者的中文指南都把「软件安全包络 / 碰撞恢复 / 看门狗 / dead-man」列为
P0 未实现项。无硬件急停、无 ARMED/DISARMED/FAULT 状态机、无软件碰撞检测是六个项目的共同缺口。

## 6. DexMani Real 实验室简化方案

### 6.1 目标与适用范围

本节只面向以下实验室运行条件：操作者全程在场、低速、固定工位、工作区在运行前清空、硬件急停可用，
且不做无人值守运行。目标是减少 DexMani Real 的机制和状态组合数量，不以复制参考项目已确认的安全缺口
为手段。

参考项目给出的有效最小基线是 LeFranX 的**硬动态限制 + 0.5 s 命令 stale hold + 固件碰撞阈值**。
但 LeFranX 的 1 kHz Franka/Ruckig 控制结构不能直接搬到 xArm Mode 6：DexMani Real 由 Mode 6 固件平滑
端点，应用层插值会改变控制器语义并可能诱发过冲/C24（`CLAUDE.md:163-166,292-297`）。可借鉴的是
“限制、超时、保持”的安全目标，而非其轨迹生成结构。

### 6.2 对“直接删除清单”的 fact-check

| 提案 | 判定 | 当前事实与处理 |
|---|---|---|
| 将 `DISARMED/ARMED` 合并为 `STOPPED` | **不采纳** | 两者对应不同物理控制器状态：`DISARMED/FAULT` 确认 xArm State 4，`ARMED/RUNNING` 确认 Mode 6 / 控制器上报 State 2（`robot/arm_loop.py:672-705`）。保留四态。 |
| 删除 `run_generation` | **不采纳** | 它同时使有序 arm 队列、latest-wins hand ring 和推理候选中的旧命令失效；单个整数的复杂度低于可靠清空多种 IPC 原语，也是命令静默暂停的核心边界。 |
| 删除 `observation_id`、current-tick mailbox | **条件删除** | 仅在实验室核心完全不包含异步 learned-policy 部署时删除。保留异步推理时，`observation_id` 用于把候选绑定到实际快照（`policy/learned_coordinator.py:365-389`）。 |
| 删除全局 `action_id` | **不采纳** | 它不只是推理元数据，还关联普通 endpoint 的 worker 执行反馈和录制追踪。回零另有独立 `request_id`。 |
| 删除 inference 隔离、camera generation 与 re-warm | **条件删除** | 可随 learned-policy 整条能力一并移出实验室核心；若保留异步视觉策略，则这些机制处理相机重启和旧候选，不能单独删除。 |
| 删除各 worker readiness/heartbeat | **不采纳** | 当前主监督器以已启用 worker 的死亡和心跳超时进入 `FAULT`（`runtime/supervisor.py:96-114`）。可减少启用的 worker，不能让仍控制硬件的 worker 失去监督。 |
| 删除 `ComponentPhase/FaultCode` 状态层 | **可采纳为诊断减量** | `publish_component_status()` 当前不写共享健康状态，只输出结构化日志（`shm/shared_storage.py:570-589`）；删除这些诊断枚举不改变 ready/heartbeat/sticky error 的安全判定。 |
| 删除优先停止环与 ACK | **采纳（2026-08-14 最终决策）** | 普通暂停改为 LeRobot 风格的命令门控：推进 generation、停止发布，让控制器完成最后一个已接受 endpoint；恢复前从最新反馈重锚。State 4 只用于 DISARMED、FAULT、紧停后备与最终退出。 |
| 删除 C24 自动恢复，任何控制器错误人工复位 | **不采纳（2026-08-14 最终决策）** | 保留一次有界的 C24 measured-hold 恢复；它是控制器错误恢复，不属于普通暂停。2 秒内再次出现 C24，以及 C22/C31，仍进入粘滞故障。 |
| 删除在线通用软件碰撞检查 | **提案前提不成立** | 通用 SafetyGate 已在 2026-08-12 移除速度包络、碰撞和过渡几何，只保留格式、限位和工作空间（`policy/safety.py:52-72,107-193`、`CLAUDE.md:120-131`）。现存碰撞检查集中在 VR IK、回零和 replay，不能视为同一个在线通用层。 |
| 固定回零路径替代 detour/RRT | **条件采纳** | 只有在限定并验证允许回零的起始姿态集合后成立。当前 direct、proximal-first、distal-first、RRT 均重新密集检查，全部失败即保持（`planning/path_utils.py:356-413`）。 |
| 删除 live replay | **采纳为范围裁剪** | live replay 已是独立入口且默认 dry-run，不属于遥操作数据采集核心；不启用即可，删除它不会简化正在运行的 teleop 控制环。 |
| 合并 XHand controller/worker/driver 检查为一层 | **不采纳** | controller 检查防止 arm 已发布而 hand 后置拒绝导致失配（`teleop/hand_control.py:17-59`）；worker 防 IPC/代际/过期/机械边界，driver 是 SDK 前最终边界。可以复用校验逻辑，不能删除边界。 |
| 将录制错误与机器人 `FAULT` 解耦 | **大部分已经实现** | 普通 start/write/overflow/codec 错误只中止 episode，不锁存机器人故障（`recording/io_process.py:811-1006`）；只有 recorder 进程死亡/心跳超时仍由通用 supervisor 视为 worker fault。 |
| 用 LeFranX/Ruckig 直接替换现有运动限制 | **不采纳** | LeFranX 的 Ruckig 硬限和 0.5 s stale hold 已核实，但 xArm Mode 6 禁止应用层插值。只借鉴命令流超时语义。 |

2026-08-14 的暂停决策具体借鉴 `lerobot_ufactory` Pika/UMI 的
`_teleop_enabled` 门控语义：关闭门时冻结命令发布，重新启用时从实测状态重锚。DexMani Real
额外推进 `run_generation`，使有序 arm 队列、latest-wins hand ring 和异步推理 mailbox 中的旧项
在 worker 边界失效；这不是急停，也不能撤回固件已经接受的 endpoint。最后一个已被控制器接受的安全
endpoint 允许自然完成，手部保持最后一个已接受目标，但两侧都不接收新的普通暂停替代 action。

### 6.3 推荐的实验室核心范围

以**有人值守的 VR 遥操作与数据采集**为核心；learned-policy 部署和 live replay 不进入最小运行配置。
核心只启动实际需要的 arm、hand、VR、policy，以及录制时才需要的 camera/recorder。当前入口已经按能力选择
进程（`examples/collect_teleop.py:237-293`），因此简化首先是缩小产品范围，而不是让所有进程继续存在后再
拆掉保护。

#### 保留

1. `DISARMED / ARMED / RUNNING / FAULT` 四态及粘滞故障；状态机很小，且直接表达 xArm State 4 与
   Mode 6/State 2 的物理差异。
2. 软件急停，以及普通暂停的 generation 失效、命令静默和反馈重锚。
3. 单一 SafetyGate 的 shape、NaN/Inf、表示/单位、arm/hand 关节范围和固定工作空间检查。
4. 遥操作上游的 arm/hand command-to-command 增量限制；xArm 速度/加速度继续由 Mode 6 固件执行，
   不增加应用层插值。
5. `run_generation`、命令有效期和 worker 边界复核；不恢复执行暂停前或排队过久的动作。
6. 已启用 arm、hand、VR、policy 的 readiness、心跳、进程死亡监督和验证式关机。
7. xArm 固件碰撞保护、SDK 返回码检查、VR IK 候选碰撞检查和回零路径碰撞检查。
8. XHand 发布前整组动作检查，以及 worker/driver 的机械范围和增量兜底。

#### 简化

1. **错误恢复收敛**：只保留一次有界的 C24 measured-hold 恢复；2 秒内重复 C24 与 C22/C31 均进入 `FAULT`。
   不采用 PF-DAG 式循环 `clear_error→motion_enable`。
2. **组件诊断减量**：删除实验室核心中的 `ComponentPhase/FaultCode` 枚举及状态日志调用；安全决策继续
   只依赖 ready、heartbeat、进程存活、sticky error 和四态。
3. **故障规则统一化**：任何已启用 worker 死亡或心跳超时仍统一进入 `FAULT`，不新增按组件分级的
   恢复状态；普通 recorder episode 错误维持现状，仅中止录制。这样保留一个故障规则，也避免控制源
   已死亡时还需要 Main 新增动作发布职责。
4. **回零候选收敛**：若实验规定只能从一个已验证的起始姿态包络回零，保留一条固定低速里程碑路径和
   fail-closed 检查，删除 detour/RRT fallback；起始姿态不在包络内时禁止自动回零。
5. **配置收敛**：保留实际进入安全判定的限位、时间、工作空间和固件参数；诊断阈值与安全阈值分表，
   删除无消费点字段，避免参考项目普遍存在的“声明但未生效”。

#### 从实验室核心条件删除

1. 整条 learned-policy 部署能力：inference 子进程、tensor block、current-tick candidate mailbox、
   `observation_id` 因果绑定、PolicySpec 部署资源哈希、camera-generation re-warm。以后需要实机策略时
   作为独立高级配置恢复，不能保留异步推理却只删除其时效/代际保护。
2. live replay 及其实机 preflight。离线 episode 读取、质量分析和可视化不属于运动安全，可保留。
3. 回零 RRT/detour，仅限上一节定义的固定起始姿态包络成立时。
4. recording provenance、fsync、解码复核和原子发布不计入机器人运动安全复杂度；它们属于数据完整性，
   是否保留由数据质量要求决定，不应为了精简安全状态机而联动删除。

### 6.4 明确不删除的最小安全内核

最终最小内核不是“三态 + 单循环”，而是：

```text
四态生命周期
    + shape/finite/关节限位/工作空间/遥操作增量门
    + run_generation/命令过期
    + enabled-worker 心跳与进程监督
    + 普通暂停的命令静默和恢复重锚
    + 固件碰撞/速度/加速度后备
    + C24 一次有界恢复，重复/其他设备错误 FAULT
```

相较当前项目，真正删除的是**高级能力及其专属协议**和**自动恢复/通用路径搜索分支**，而不是低成本、
跨暂停和跨进程直接阻止旧命令或失控运动的安全内核。这也避免退化为参考项目中已确认的问题：无命令
stale 语义、无有限值检查、无状态归属、无限自动 re-arm 或仅依赖固件。
