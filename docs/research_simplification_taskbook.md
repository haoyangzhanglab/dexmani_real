## 1. 目标与取舍

面向个人机器人研究，减少需要同时理解和维护的状态、协议、进程与时间门槛。让实际资源、实际结果和直接控制流承担职责，不再围绕它们维护第二套表示。

- **不考虑旧接口兼容。** 同步修改本仓库实际调用方、测试和文档；删除旧参数、旧字段及无人使用的分支，不保留别名、迁移层、双实现开关或旧测试假设。
- **允许明确的行为放宽。** 成功的 ARM 操作不再因父进程稍晚消费回复而失败；HOME 规划允许使用入口前取得但仍新鲜、低速的反馈。保持原始时间真实，不新增宽限时间配置。
- **不以“参考项目没有”作为删除证明。** 删除重复事实；保留真实副作用、并发、数值转换和资源所有权边界。
- **不扩建平台。** 不新增 Manager、通用状态机、取消上下文、结果包装类、缓存服务、重试框架或可配置的新旧策略。
- **音频继续播放。** 保持当前单待播槽、尽力播放和有界关闭，不增加精确交付、抢占或退出排空协议。
- **架构减法必须改善实际使用。** 场景点云迁入模型线程是明确的首选候选，但是否删除独立进程，以代表输入和现有预测预算验收；不以减少文件数代替测量。

先读 `AGENTS.md`、当前 HEAD 和工作区改动。基线之后已完成的任务直接核验，不重复实现，不覆盖他人工作。

## 2. 两轮结论汇总

| 发现 | 性质与证据 | 本轮决定 |
| --- | --- | --- |
| SensorWorkers 在 `process.start()` 返回后才登记 | 既存资源归属缺口；真实 spawn 子进程启动后注入中断，登记为空，shutdown 未回收该进程 | T1：先取得资源归属，再启动；按真实句柄收尾 |
| HOME/prepare 成功回复后再次按父层时间判超时 | 既存严格策略；受控复现成功回复晚消费 0.5 ms 即失败 | T2：owner 裁决执行完成；父层保留未决等待、错误和撤权检查 |
| ARM HOME 规划要求反馈晚于函数入口 | 既存相位门槛；新鲜、低速缓存也要等下一帧 | T2：删除入口相位，保留新鲜度、速度与 owner 起点复核 |
| 触觉 reset 在初始反馈等待返回后再检查同一取消回调 | 相邻边界重复，之间没有新的 I/O | T2：删除外层尾部复查，保留内部读取前后检查 |
| PolicyWorker 的 `operation` 字符串及结果二元组 | 正式消费者不按标签分派，仍要多处同步维护 | T3：交接已完成 Future，删除标签及配套协议 |
| `color_frame_number` 在运行时多层传递 | IPC/Observation 中只有搬运，没有下游消费者；接收端与标定仍需要硬件帧号 | T4：只删除无消费者的运行时传递 |
| Policy 再按 needs 枚举需要检查的进程 | 启动流程与实际资源列表已表达同一选择 | T4：直接检查实际受管传感进程 |
| 场景点云独立进程、第二共享环及双读取路径 | 有实际并行收益，也有显著生命周期和复制成本；尚无性能结论 | T5：按需模型线程方案试验，验收后只保留一条生产路径 |

`6e91424` 已完成的生命周期短轮询、父子启动身份/期限传递、初始反馈回调收拢、Raw 数值单遍读取、Policy 先设备后 writer、投影关节重复限位删除和 HOME 中间复制删除，继续保留，不重新组织一轮相同重构。

最近审查的隔离用例不是完整 pytest，也不是硬件验收。历史通过数量不能直接作为本任务实施后的验证结果。

## 3. T1：让传感进程从启动尝试开始就有 owner

主要位置：`dexmani_real/runtime/lifecycle.py`，以及 SensorWorkers 的正式调用方和测试。

1. `may_start` 和既有资源健康检查通过后，在调用 `process.start()` **之前**登记进程对象。把 `started` 改为符合新语义的资源列表名称，并更新实际引用；不另加一份 started/successful/cleanup_needed 标记。
2. 启动失败或中断原样向外传播，仍由统一收尾处理已归属对象。沿现有外层中断路径锁存急停，不为本修补给所有 start 回调再注入 SessionState。
3. shutdown 按进程对象的真实状态收尾：确定未启动的对象不调用会断言失败的 join；已启动对象执行现有有界回收；仍存活或无法确认退出的对象保留归属并报错。不能用 `exitcode is None` 单独把未启动对象判成残留运行进程。
4. 一项关闭失败不跳过其他资源；保留主错、中断身份和真实未回收句柄。现有 terminate/kill 升级只用于传感进程，不能迁移到 ARM SDK owner。
5. 本任务修复可观察进程句柄的归属窗口，不宣称 Python 层能保证任意 native 创建中断都不存在不可观察的 OS 副作用。

验收：正常启动；启动前失败且无 PID；已有 PID 后抛错/中断；多个传感器中一个启动失败；关闭时仍有活进程。采用同步点或在真实 start 返回后注入异常，所有测试创建的进程最终必须回收。

## 4. T2：收拢时间裁决和相邻重复检查

### 4.1 ARM 成功回复不再做父层时间判罚

主要位置：`robot/xarm7/process.py::request_operation()`。

删除“收到 `None` 成功回复后，仅因父层当前时间已越过 deadline 而抛 `arm operation completed after deadline`”的分支。

新的职责明确为：

| 边界 | 保留的职责 |
| --- | --- |
| 请求提交前 | 设备可用、预期代际、取消及未过期 |
| owner 执行期间与完成前 | 操作总期限、阶段期限、真实到位/停稳、最终取消检查 |
| 父层等待未决回复 | 有界等待、服务故障和取消；未确认成功时超时仍失败 |
| 父层消费成功回复 | 保留故障与撤权复查；不再仅以消费回复的时间追加失败 |

错误回复、SDK TimeoutError、晚到设备故障、子进程异常退出和操作者撤权不能因放宽而变成成功。沿现有检查和收尾传播，不新增成功 ACK、完成时间字段或异常协议。

一旦父层已经因超时/取消进入收尾，随后收回的成功回复仅用于完成资源回收，不能逆转原来的终止决定。启动 ready 等待、真正未决任务的超时、动作租期和 RTC 交接期限不随本项放宽。

### 4.2 HOME 规划信任仍有效的实测反馈

主要位置：`runtime/home.py::home_arm()`。

删除 `boundary_ns` 和机械臂 `timestamp_ns > boundary_ns` 的入口相位条件。允许使用函数入口前取得、但当前仍新鲜且实测速度满足阈值的反馈进行规划。

保留设备停止流程、臂和手的新鲜度、速度门槛、规划后的取消检查、owner 执行前停稳与实际起点复核、路径/碰撞检查、各段到位和最终 canonical target 检查。若实际起点与计划不符仍拒绝，不增加自动重规划。

`home_hand()` 中提交完成之后的新样本确认用于证明本次命令效果，继续保留；不要因代码都比较 timestamp 就一起删除。

### 4.3 删除触觉 reset 的尾部重复取消检查

主要位置：`robot/system.py::reset_tactile_sensors()`。

`_read_initial_state()` 已负责读取前后的综合回调和反馈准入。删除它返回后紧邻的额外 `if cancelled()`；保留内部两次检查、等待期限和后续设备授权边界。

回调仍负责当前操作的完整故障/取消语义。触觉 reset 自身会主动停止设备，不能新增“stop 为真就取消”的通用判断；不再删除不同 I/O 两侧的检查。

## 5. T3：模型完成交接直接使用 Future

主要位置：`deployment/inference.py`、`deployment/session.py`、`deployment/rollout.py`。

1. 删除 `PolicyWorker.operation`、`_submit(operation, ...)` 的标签参数、load/warmup/predict 标签字符串及提交/消费/丢弃/关闭时的配套维护。
2. `poll()` 无已完成项时返回 `None`；有已完成项时从 worker 取走该 Future，清除当前任务引用并返回 Future。交接的是已有标准对象，不新增完成标记或结果包装类。
3. `wait_model()` 检测到完成项后立即调用 `future.result()` 再结束等待；load/warmup 正常返回 None 仍表示成功完成。`Rollout.poll_model()` 同样取得 `future.result()` 后再执行现有 action shape/finite 检查。
4. 所有正式消费点都必须调用 result，不能只看 done。不得改成“原始结果或 None”，否则成功的 None 会和未完成混淆。
5. `_submit()` 对尚未回收 Future 的拒绝不变。`discard_pending()` 的等待、异常传播、超时保留归属，以及同一模型线程的 load/warmup/predict/close 不变。
6. 退休任务错误保留原异常及 traceback，日志无需再复制操作名标签；close Future、中断锁存和关闭等待语义不变。

验收：未完成与成功 None 可区分；预测结果正常；load/warmup/predict 的异常均传播；任务自身 TimeoutError 不成为 pending；done 未消费仍拒绝新提交；退休失败仍执行 close；调用线程所有权不变。

## 6. T4：只维护实际使用的资源和字段

### 6.1 Policy 健康检查依赖实际受管进程

主要位置：`deployment/session.py::check_services()`。

保留键盘健康检查及其急停语义。删除按 `needs.camera_worker / needs.point_cloud` 再筛选进程名称的循环，改为直接检查 SensorWorkers 的实际受管进程，失败用现有 RobotError 通道报告；底层日志继续带进程名。

核对启动流程：只启动必要进程；仅用于静态参数的相机在进入运行阶段前已关闭；关闭成功后资源列表为空。启动阶段也应检查已取得归属的资源，未到启动步骤的资源不通过另一份“期望列表”补查。

Teleop 仍按来源区分控制服务故障与录制相机故障，保留它需要的名称筛选。不要为了统一外观新建通用健康报告对象。

### 6.2 删除运行时 color_frame_number 搬运

涉及 `sensor/realsense.py::run_camera()`、`ipc/sensors.py`、`perception/worker.py`、`runtime/observation.py`。

删除 camera/pointcloud IPC payload 中无人消费的 `color_frame_number`，以及对应字段选择、复制、整数转换和 Observation 字典项。T5 若直接删除点云 IPC，则相应代码整段删除，不先改后留兼容壳。

保留 RealSense 接收端的 depth/color 硬件身份、重复帧识别和首次接收时间；保留 `RGBDFrame` 及相机标定真正使用的硬件帧号。保留 Raw 的 `ring_sequence` 和现有点云路径的 `source_camera_sequence`，它们有真实配对职责。

收益是减少跨层字段维护，不承诺仅删一个标量就带来明显提速。无需修改 Raw 或 checkpoint 的语义来配合内部 IPC 清理。

## 7. T5：按需构建场景点云，验收后决定删除独立进程

这是本轮唯一需要性能证据的架构取舍。**首选最终形态：相机进程只提供 RGB-D 快照，场景点云与手部几何一起在现有模型线程构建；不新增线程或执行器。** 先在隔离改动中验证，满足本节条件后才用它替换生产路径；不要求为了完成勾选而强制删除有用的并行计算。

### 7.1 首选实现

1. `ObservationBuilder` 根据 checkpoint 模态明确内部依赖：需要场景点云就取得配对 RGB、depth；与录制需求继续做现有并集。主线程只取得独立快照和保存控制历史，不在控制循环中新增重型点云计算。
2. 会话在启动时读取并保存相机、外参、深度比例和必要桌面参数，再配置观测构建器。沿现有 configure_camera 或相同职责入口传递，不在每次推理中读标定文件，不新增参数广播协议。
3. 复用同一个 `PointCloudProcessor` 和 checkpoint 恢复的配置，保持滤波、裁剪、采样算法与导出 recipe 一致。只移动计算归属，不借本任务更换算法或数值默认值。
4. 在现有 `PolicyObservationRow.features` 中缓存实际消费行的派生结果。点云单模态、没有 arm FK 的路径也必须计算；warmup 多次引用同一行只计算一次。每行所需派生特征全部成功后再提交缓存，不把部分非空 features 误当成全部完成；不增加 ready 布尔、跨 episode 缓存、帧号哈希表或缓存管理器。
5. 同一份 RGB-D 同时产生该行图像输入、点云输入和 Raw 记录。保留来源时间，点云计算完成不能刷新相机年龄。历史长度仍由 checkpoint 控制；不为了缓存保留整段图像。
6. 点云构建计入现有预测等待和 RTC 交接预算，不延长 deadline 掩盖成本，不调整承诺槽，也不把处理移回控制线程来假装推理更快。

### 7.2 明确接受的语义变化

旧 worker 无有效点时不发布，消费者可能继续使用尚未过期的上一份结果。首选新方案取消这层隐式持有：实际用于模型的某行生成空点云时，立即以明确的观测构建异常结束当前运行，沿既有异常/收尾路径报告；启动预热也不得伪装成功。允许该错误使本次会话失败，不新增可恢复输入协议或自动重试。

不送空数组/零云给模型，不混用别行图像与旧点云，不跳过历史行、不自动补齐窗口。此项改变输入选择与失败时机，必须在 README 和实施报告中写明，不能声称完全行为等价。

### 7.3 通过后整组删除

- 独立 pointcloud worker 入口、进程创建、就绪等待期限及专门健康检查。
- `pointcloud_ring`、对应 dtype、相机载荷转交及其分配参数。
- Observation 中“读 camera ring / 读 pointcloud ring 附带相机”的双路径。
- 不再有消费者的独立 pointcloud 时间字段和点云 IPC 配对字段。
- recorder 仅为丢弃预先计算点云而创建的行替换，以及上述结构的无人使用参数、导入、测试假设。

保留模型输入键 `point_cloud`、处理 recipe、来源新鲜度、数据导出的点云功能和真正被使用的 `ObservationNeeds.union()`。不做跨仓库兼容桥接，不让旧生产路径与新路径长期并存。

### 7.4 测量与准入

用代表性 Raw、实际分辨率/点数、checkpoint 历史长度和混合模态，比较旧路径与首选路径。模型可用时测量完整“构建观测＋推理＋完成交接”，不能只测一个点云函数；预热和正式循环分开记录。

验收至少包含：

- 同一输入和配置的有效点云数值/形状/dtype 一致，图像配对和来源时间一致；覆盖点云单模态、RGB-D＋点云、手部几何混合输入、重复引用和空云。
- 记录完整查询延迟的 p50/p95/p99、峰值内存和实际已有预算余量；这些是测量结果，不新增运行配置或准入状态。
- 在相同调度回放下，代表性的 sync/async/RTC 用例没有因迁移新增预算耗尽或交接失败；确认额外图像保留和处理成本可接受。不能靠放宽 RTC 或目标租期通过。
- 多段运行仍回收上一段模型任务，缓存随原行生命周期释放，没有新增后台任务或跨段结果。

如果缺少代表数据/checkpoint/依赖，或实测不能满足已有调度预算：完成 T1–T4，**保留现有唯一点云生产路径**，如实将 T5 标为待验证或本轮不采用，写明缺失证据/瓶颈。不要合入未验收的切换、留下开关，或因测量受阻而阻塞其他明确改动。无需建设 benchmark 框架、常驻指标服务或自动调参器。

## 8. 必须保留的边界

| 保留机制 | 实际职责 |
| --- | --- |
| 共享 emergency、父层本地撤权、运行代际、prepared_run_id | 急停事实、迟到动作隔离、设备准备资格；不是重复状态 |
| 原子 begin_motion 和 SDK 前检查 | 等待/计算后授权可能变化；不能由入口检查替代 |
| 组合命令副作用前预检、SDK 返回码 | 防止半个组合目标执行后才发现另半个非法，保留真实设备失败 |
| 来源新鲜度、提交机会、目标租期 | 分别约束数据年龄、决策时机和断流；本轮只放宽已指出的相位/回复消费门槛 |
| HOME 路径、停稳、起点及 canonical target 检查 | 几何和实测状态职责；不因参考项目代码短而删除 |
| Policy HOME 起点约束 | 属于 checkpoint 初始状态分布要求，不是旧接口兼容；没有模型证据不改成任意姿态开始 |
| sync/async/RTC、history 完整性、Ruckig 发送成功后 commit | 实际研究语义、模型契约及已提交参考 |
| 首次 finish、Raw staging、整段/整批拒绝、writer/model 独立预算 | 唯一发布决定、失败诊断和真实资源回收 |
| 模型/设备单一 owner、真实 pending 句柄 | 不用清空字段、daemon 化或忽略异常假报完成 |
| SharedRing 的复制与一致性检查 | 防止并发写入期间读取混合帧；latest-only 不等于可以随意删除复制保护 |

已发布 Raw 后发生模型回收失败，仍只影响 episode/session 结果，不反写已发布 Raw。普通音频故障仍只 warning；真实中断锁存急停。不要借本轮重写 ARM close_error 协议或再建全局错误聚合器。

## 9. 执行顺序与验收
