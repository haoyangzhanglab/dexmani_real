状态：**已实施，离线回归通过**。2026-11-03 在 `real_robot` 环境禁用 pytest 缓存运行 `tests/`：237 passed。验证包含真实 Ruckig、HDF5/MP4/Zarr；设备、终端和播放器进程使用外部边界替身。未连接真机，未验证物理停稳、真实 checkpoint 推理或实际声卡播放。下文保留审查基线时的判断和任务要求，不代表当前仍存在这些待办。

审查基线：[`85b6174920025833d6e300548789a246a1ad6076`](https://github.com/haoyangzhanglab/dexmani_real/commit/85b6174920025833d6e300548789a246a1ad6076)，2026-11-03。本文合并最近两轮的修复验收、生命周期审查及三个参考项目对照。实施前读取当前 `AGENTS.md`、工作区改动和相关调用链；后续提交已解决的项目直接验收，保留他人修改，不按旧行号机械打补丁。

## 1. 目标与最终形态

让研究者容易回答：现在能否运动、这条命令属于哪一段、谁负责关闭资源、这份数据为什么被接收或拒绝。删掉重复表达这些事实的字段、检查和协调协议；保留真实的硬件、并发和数据边界。

最终采用以下职责划分，不新增架构层：

| 事实或职责 | 唯一权威来源 / 执行位置 |
| --- | --- |
| 本次运动身份和授权 | 现有 `SessionState`；`begin_motion(run_id=...)` 原子准入 |
| SDK 实际提交前是否仍可运动 | 设备 owner 的现有代际、停止、期限和反馈检查 |
| 操作者本批次希望开始哪一段 | 主线程函数的返回值和局部 `run_id`，不再保存启动邮箱 |
| 模型任务是否回收 | `PolicyWorker` 的真实 Future；正常 Rollout 返回代表本段资源已收尾 |
| 是否保存、如何结束一段 | 现有首次 finish 决策；结果记录事实，不反向控制生命周期 |
| 控制时刻 | 一个下一次计划时刻；Raw 另存实际读取开始、结束和各来源时间 |
| 音效 | 一个后台播放线程、一个待播槽；尽力提示，不参与实验成功判定 |

不新增 Manager、事件总线、通用状态机、清理聚合器、结果包装层、兼容开关或可配置的多套新旧行为。不要为了减少代码行数合并不同事实，也不要为每个局部检查再建一个工具函数。

## 2. 两轮发现的合并结论

以下判断基于源码与已有隔离离线复现；“已修正”表示实现已到位，不表示完整依赖测试或真机验收已通过。

| 项目 | 当前判断 | 本任务决定 |
| --- | --- | --- |
| 运行期限被等待期限覆盖，错误归因为预测超时 | `85b6174` 已修正 | 保持独立期限和相等时运行时长优先；补回归 |
| 四处重复的 begin-motion 代际授权 | 已集中到 `begin_motion(run_id=...)` | 保留，不退回调用方协调 |
| Session 空闲入口重复 pending 准入、stop/quit wrapper | 已删除 | 不重新引入；验证 Rollout 失败后不能进入下一段 |
| Jog 的迟到 R 在 HOME 后重新执行 | 已修正输入身份资格 | 保留；Replay 的 H 仍需独立修复 |
| 异常 episode 裁剪为训练前缀 | 已改为完整验证、整段拒绝 | 保留，禁止恢复裁剪、自动跳过坏段或重采样兜底 |
| 关闭中断丢失急停语义 | 多数边界已修；ARM 操作回滚和键盘终端恢复仍有缺口 | T1 局部修复 |
| Session 启动意图、准备键清队列 | 仍与代际和主线程控制流重复 | T2 删除；先补齐 Replay HOME 结束边界 |
| 模型关闭返回错误字典列表，Session 再归并 | 仍有异常与数据两套失败通道 | T3 用 Future 的正常异常通道收拢 |
| Teleop 首读结束时间被用作时钟原点 | 会使首读成本错位，影响后续采样和首轮预算 | T4 修正；不得靠放宽导出掩盖 |
| 全段首帧绝对相位硬门槛 | 对微小持续偏差过严，且不是训练采样器的直接契约 | T4 删除，改成局部间隔和平均周期检查 |
| 音效的抢占代际、FIFO、活动请求、退出排空 | 超出个人实验提示所需 | T5 保留播放，删除精确交付协议 |
| HOME 中对手部重新制造“函数入口后样本”条件 | 手部已确认 HOME 后又叠加时间门槛 | T6 删除该重复门槛；保留真正的新鲜度和收敛检查 |
| `capture_ids`、历史 episode 错误扫描、混用 epoch/run_id | 可由已有事实或局部数据流表达 | T7 删除或统一 |
| HOME 路径搜索、运行代际、三种策略调度 | 独有不等于无用；删除会改变实际能力 | 本轮保留，见第 5 节 |

本文调整了早先“保留 `start_epoch`”的建议：同批 B→H/T 的排斥可由主线程直接返回选中的 B 实现，无需成员字段。此前“保留所有时间检查”的结论也收窄为：保留真实来源和动作时效，放宽训练数据的全局相位要求。

## 3. 实施任务

### T1 — 补齐真实中断边界，不扩建错误处理框架

涉及 `robot/xarm7/process.py`、`robot/system.py`、`runtime/keyboard.py` 及对应关闭调用方。

**ARM 操作回滚。** `request_operation()` 捕获原错后仍会停止、消费本请求回复、等待停止。其中二次 `KeyboardInterrupt` 目前可能只进入错误列表；原 `OSError` 继续抛出，但急停没有锁存。

1. 父进程的 `ArmProcess` 在构造时接收并保存现有 `runtime_state`，从它取得三个共享信号；相应删除构造参数的三份传递和 `close(runtime_state)` 的重复注入，统一为 `close()`。唯一生产构造处和测试一起更新，不保留双签名。
2. 子进程接收配置、IPC 通道、Pipe，以及父层捕获的启动身份和绝对期限；不传整个 `SessionState`，不改变锁与进程所有权。
3. 在原错及回滚实际捕获 `KeyboardInterrupt` 的边界立即调用 `request_emergency_stop()`，随后继续应做的回复回收、停止确认和关闭；原来的运行主错保留。
4. 原来仅为 `OperationCancelled`、但收尾实际失败时，仍升级为收尾故障；未确认停止或回复消费时仍禁止复用 owner。不要为“统一首错”把故障降为普通取消。

**Keyboard 关闭。** `listener.stop/join()` 的中断可能被 `finally` 内终端恢复的 `OSError` 覆盖。

1. 依次尝试 `listener.stop()`、有界 `listener.join()` 和终端恢复；单项报错不阻止余下步骤，保留首错并记录后续 traceback。
2. 任一阶段捕获到真实 `KeyboardInterrupt`，立即在 `Condition` 锁外调用已有 `estop_callback`。此时 `active=False`，不能依赖会提前返回的 `latch_emergency_stop()` 来补锁存。回调本身的异常也不能覆盖首错或跳过终端恢复。
3. `saved_termios` 的释放归属明确；停止后的事件和 held-key 清空保留。没有 listener、重复 stop 等已有合法路径仍可用。

共同规则：普通音频异常不升级为实验故障；真实中断不被改名为普通数据错误。收尾仍尽力覆盖全部核心资源，保留真实 pending 句柄、主错和非零退出结果；不新建全局异常聚合器，也不把所有 `BaseException` 捕获机械改为 `Exception`。

### T2 — 用返回值和代际替代启动邮箱与准备键清理

涉及 `deployment/session.py`、`deployment/rollout.py`、`teleop/loop.py`、`teleop/run.py`、`teleop/keyboard.py`、`replay/run.py`、`runtime/keyboard.py`。

**先补 Replay HOME 的结束边界。** `wait_for_home()` 中，在每次 HOME 尝试的 `finally` 使用现有撤权操作结束该代际，包括成功、取消和可恢复几何拒绝。HOME 期间已取身份、尚未入队的 H 必须因此失效。仍允许结束后新按的 H；已完成的回放结果不因一次干净的 HOME 几何拒绝改为 fault。

**再删除 `start_epoch`。** `handle_command_batch()` → `poll_operator()` → `run_control_loop()` 直接返回并传递 `int | None` 的启动 `run_id`：

- 全批次先处理 Esc 和 S/C/D/Q 的抑制优先级；已有键盘回调仍先撤权，不能延迟到主循环才停止。
- 有效 B 直接返回其 `run_id`，不再处理本批后续 H/T/B。因此 B→H、B→T、重复 B 仍只请求一次启动。
- 有效 H/T 执行完便结束本批，不留下下一段启动意图。手部禁用的 T 保持无操作语义；旧身份或不符合入口条件的准备事件跳过，不能阻挡后面的有效事件。
- 主循环仍先 `service_idle()`，再验证这个局部 `run_id` 是否仍满足现有 ARMED 准入，之后才创建 Rollout；准备完成后的实际启动仍经过 `begin_motion()`。
- 运行或收尾中的 `episode` 仍排斥新的 B。删除字段、`request_start()`、取出并清空代码和 H/T 对启动邮箱的检查，不用新布尔字段替换它们。

**最后删除准备键 `discard_events()` 机制。** 基线有 11 个调用点。逐处核对“进入准备前身份”和“完成/取消/收尾后的代际边界”，再移除清队列及无人使用的 API。

- 每个准备事件在实际派发时核对身份与既有入口资格；不能在批次开头过滤一次就认为余下事件始终有效，因为前一个事件可能同步运行整个 episode 并改变代际。
- Teleop 的旧 B 应跳过，不能靠它提前结束批处理；Policy 的旧 T 应在占用本批准备机会前跳过；Replay 应寻找首个当前有效 H，不能先拿旧 H 后忽略同批新 H。
- Jog 保留“只有 RUNNING 时读取的 R 才带可执行身份”的规则；不要新增 input generation、busy epoch 或 ready 标志。
- 保留真正的撤权操作，尤其是收尾末尾那次撤权。它覆盖尚未入队的迟到事件，与停止设备时的撤权职责不同。
- 保留 `Keyboard.stop()` 的资源性队列清空、正常 `poll()` 消费，以及实际运动提交前的授权复查。

### T3 — 模型关闭直接完成或抛错，Session 只负责结果序列化

涉及 `deployment/inference.py`、`deployment/session.py`。

`PolicyWorker.close()` 仍将关闭任务排到同一个模型工作线程：先消费退休任务，再关闭模型。两项都尝试；保存首个真实异常，后续异常记录 traceback，任何捕获的 `KeyboardInterrupt` 立即锁存急停，最后由 close Future 抛出首错。

删除 worker 内的 `error_detail()`、错误字典列表返回值及 Session 的 `model_errors` 合并协议。不要新建错误容器或统一 Result 类型。

把 `wait_closed(timeout_s)` 缩成一个明确契约：

- 用 `concurrent.futures.wait()` 判定预算内是否完成；尚未完成返回 `False`，保留 close Future。
- 确认完成后调用 `future.result()`；正常返回 `True`，失败直接传播原异常。
- 模型自身抛出的 `TimeoutError` 是已完成任务的失败，不能再因 `FutureTimeoutError` 别名捕获而被记为 pending。

Session 在一个结果边界将上述事实转换为现有 `completed / failed / pending` 和 JSON。等待本身遭中断时，按 Future 的实际完成状态区分 failed/pending；急停锁存，后续结果保存仍尝试。

明确报告语义：主错和资源状态进入结构化结果；二次关闭错误的完整 traceback 保留在日志，不承诺每个二次异常都再复制为一条 JSON。不要为这个调整重写全仓错误格式。writer 与模型各自独立的收尾预算、模型未回收禁止复用、线程所有权不变。

### T4 — 修正采样起点，放宽全局相位，保持时间事实真实

涉及 `teleop/loop.py`、`utils/timing.py`、`data/export.py` 及数据与控制测试。

**运行时只维护下一次计划时刻。**

1. 首个控制槽位以读取开始时间为原点，使用 `row.control_timestamp_ns`；绝不能使用读取结束的 `observation_timestamp_ns`。首个提交期限为开始时间加一个周期，读后也必须检查该期限，首读耗时完整计入。
2. 将 `tick_origin_ns + tick_index` 的调度表示收拢为单个 `next_tick_ns`。到期后以 `planned += ((now-planned)//dt)*dt` 跳过完整错过的槽，只尝试当前槽，期限为 `planned+dt`；不能因微小迟到就总跳到未来而永远不执行。完成后推进下一槽；本槽已经失效时复用现有跳到未来时刻的算法，不补发历史 tick，不以读取结束时间不断重置时钟。
3. 本轮读取已经跨过提交期限，记录事实并跳过本轮目标计算/发送；实际 SDK 前的期限和撤权检查仍执行。保留必要的制动/停止语义。
4. `tick_index` 若只为调度及重复诊断存在即可删除；诊断直接使用计划期限和实际时间。将录制最长时长表达为由 `started_ns` 派生的一个纳秒 deadline，替换 `capture_started_s`，保持原来仅在相应录制分支生效的语义。
5. 不为了这次收拢重写 sync / async / RTC 的时间契约，尤其不能把 RTC 承诺槽改成可随意跳过。

**导出取消全段绝对相位门槛。** 设实际控制开始时间为 `t[i]`、行数为 `N`、名义整数周期为 `dt`：

| 项目 | 新规则 |
| --- | --- |
| 首帧相位累积偏差 `t[i]-t[0]-i*dt` | 不再作为拒绝条件；现有最大偏差统计可留作诊断 |
| 相邻控制间隔 | 保持现有 `abs(diff(t)-dt) <= dt//4`，防止缺帧、重复帧和明显局部间隔异常 |
| 全段平均采样周期，`N >= 2` | `abs((t[-1]-t[0])/(N-1)-dt) <= 0.05*dt` |
| 单行 | 保留无间隔可验证的 warning，不做除零或伪造周期 |
| 其他时间和完整性条件 | 保持读取不跨周期、不与下一行重叠，来源时间合法且不回退，既有触觉 age、完整状态、有限值和媒体计数要求 |

平均周期的 5% 是本任务选择的简洁研究容差，不是三个参考项目的测量结论。固定在导出实现并说明含义，不新增 CLI/config 开关。可用整数等价式 `20 * abs(actual_duration - expected_duration) <= expected_duration` 避免阈值附近的浮点歧义，其中 `expected_duration=(N-1)*dt`。

这样替换原来的全局相位条件，只需要一次相邻间隔检查和一个平均值，不新增滑窗时钟校正、重采样器、训练 horizon 参数或相位状态机。平均值不保证每个训练窗口都在 5% 内；局部质量由原来的相邻间隔上限约束，不夸大此规则的精度。

明确示例：16 Hz 下 `dt=62.5 ms`，160 行均匀 `62.6 ms` 应接受；持续 `70 ms` 虽能通过原相邻容差，仍因平均周期偏差拒绝；一个 `125 ms` 间隔仍整段拒绝。均值边界 5% 接受，超过边界拒绝。新增一个 `mean_control_period_ns` 质量统计即可，单行使用 `null`。

仍原样保存真实时间戳和名义采样频率，不把实测时间改成 `frame_index/fps`。剩余任何准入失败都拒绝整个 episode；不裁剪、不自动跳过异常段、不改训练与动作单位契约。必须先修首读起点，再验收放宽规则。

### T5 — 音频保留，降为有界的尽力提示

涉及 `teleop/audio.py`、Teleop/Policy 的音频调用与关闭边界。

保留现有 WAV 素材、`aplay/paplay` 发现和 `play(event)` 入口。运行中的 begin、save、discard、home、home_done、quit、emergency 仍发出播放请求。提示不证明机器人到位、已停止或数据已通过训练准入。

采用一个后台线程、一个可覆盖的待播槽：当前声音可自然结束；等待播放的提示被后来的提示替换，避免积压。允许合并、漏播和一定延迟，不承诺每条播完、严格 FIFO 或急停音效立即抢占。急停本身完全由状态和设备路径实现。

删除音频 generation、FIFO deque、`active_request`、`interrupt=` 选项、`wait_until_idle()` 及为退出尾音设置的 5 秒 drain。同步更新所有调用，不保留无效参数兼容层。

关闭采用以下简单规则：

- 保留 `closed` 和关闭协调；`play()` 只更新待播槽并唤醒线程，不在控制线程启动或等待播放器。
- 子进程由播放线程创建和回收；关闭清除待播槽、通知退出，并使用有限等待。工作线程必须能在等待播放期间观察关闭，例如在有界的 `communicate()` 等待之间检查；不能永久堵在无期限等待上。
- `Popen` 返回后重新观察关闭，覆盖“关闭发生在创建过程中”的实际竞态；必要时终止并尽力回收当前子进程。不要为了绝对退出保证再增加抢占代际、完成 ACK 或多层状态。
- 删除 `finish(successful)`；核心资源释放后调用普通 `close()`。**退出专用 end 尾音允许取消，不再保证播放，也不为它延迟退出。** 不留下一个必然被紧随其后的 close 取消、却声称有效的 end 播放调用。保留素材无须顺手清资产。
- 缺播放器/文件、播放失败和普通关闭超时只 warning；异常有 traceback，不影响实验结果或退出码。缺依赖可禁用本次会话音频，不自动重试或引入音频状态报告。
- 主线程关闭中真实 `KeyboardInterrupt` 仍进入已有急停/非零结果路径；不能被普通音频失败规则吞掉。设备释放仍早于音频关闭等待。

音频线程可沿用 daemon；不能把这一选择扩散到模型线程或机械臂 owner 来隐藏未完成任务。

### T6 — HOME 只删重复时间门槛，保留实际可用性

涉及 `runtime/home.py`。

正式 `home_robot()` 已先执行 `home_hand()`，后者以命令提交之后的不同新鲜样本确认收敛。`home_arm()` 又要求手反馈晚于它自身的函数入口 `boundary_ns`，并没有建立新的手部动作事实。

删除这一手部 `timestamp > boundary_ns` 条件及对应“post-home”误导文案；仍使用当前真实、新鲜的手部姿态做碰撞几何。保留 `home_hand()` 提交后样本确认、手部启用条件、机械臂停止后的新鲜静止反馈和 owner 实际起点复核。

本轮不删除父层完整的机械臂静止等待、不将 HOME 改为盲直线、不新增 prepare-home RPC。规划快照与子进程实际提交发生在不同时间，不能把后者的复查当作前者永远有效的证明。

多候选路径、最近等价关节分支、逐段停稳、桌面软间隙退出和碰撞检查本轮保留。它们决定 HOME 能否从实际实验姿态返回，尚无数据表明删成单一路径后的拒绝率可接受。一次规划内的几何缓存有真实重复计算收益；不按“有缓存/候选就过度工程”机械删除。这是范围决定，不再挂一个需要新开关的双路径方案。

### T7 — 清除派生状态，压缩维护面

1. 删除 `PolicySession.capture_ids` 及 Rollout 参数和字段；Raw 目录直接使用 `EpisodeResult.index`，例如 `episode_002`。准备取消后编号可有空洞；JSON 与 Raw 使用同一编号，不追求 Raw 连续计数。验证已有目录发现流程不依赖连续编号；不要顺带迁移或重命名旧数据。
2. 删除 Session 关闭时对所有历史 `episodes[*].errors` 的再扫描。所有控制、writer、退休模型失败必须沿实际调用链传播到会话主错；成功判断显式包含 `failure is None`，不能只删 `episode_error` 条件而误判成功。每段错误仍作为诊断保存，关闭不从历史列表再造一份控制状态。
3. 只在本次涉及的授权链统一 `epoch`/`run_id` 的命名。没有第二种身份的地方统一为 `run_id`；不改数据格式、不批量重命名无关模块。
4. 同步 README：写清音频尽力语义、采样容差、HOME 保留范围、Raw 编号及关闭报告变化；压缩历史验收过程、合成误差流水账和“当轮没有 checkpoint”等记录。保留用户需要的配置、命令、单位与兼容限制。
5. 删除测试中真实按键入口之后再手工补做 `request_episode_end()` 等重复终止请求；让测试直接验证入口行为。删掉只为已移除机制服务的断言，不为实现字段逐一写镜像测试。

### T8 — 用实际边界测试完成验收

基线远端只有 `test_admission.py`、`test_data.py`、`test_interaction.py`、`test_policy.py` 四个测试模块。此前删除的一些音频、几何、轨迹和关闭测试覆盖仍有价值；按下面行为恢复必要测试，不整包复活历史测试或新增通用 fake 框架。

| 验证组 | 最少必须覆盖的行为 |

## 4. 实施次序与完成标准

按 **T1 → T2 → T3 → T4 → T5 → T6 → T7** 推进，T8 随各项补上并在最后汇总。T2 内必须先修代际边界再删清队列；T4 内先修首读起点再放宽导出。可按这些边界形成小提交，不做一个覆盖全仓的大重构。

完成后应满足：

- 已解决问题没有重新引入，剩余确认缺陷有可重复的行为测试。
- 删除 `start_epoch`、`request_start()`、准备键 `discard_events()`、worker 错误字典列表协议、`capture_ids`、历史错误再扫描、音频抢占代际/FIFO/drain 和导出绝对相位硬门槛；无平行替代状态或无效兼容参数。
- 保留音频实际播放；明确允许漏播及退出尾音取消。停止与急停无需等音效，普通音效故障不改变实验成败。
- 允许正常的小幅长期时钟漂移，拒绝明显间隔异常和整体速率不符；原始时间与整段数据语义真实。
- 主错、急停、资源未回收是三个可以同时成立的事实；不能为了简短而抹掉其中之一。
- 已运行检查列出真实结果，未运行检查列出原因；README 与最终实现一致。不要用减少行数、语法通过或参考项目更短替代验收。

最终交付说明只需写：删了哪些机制、保留了哪些边界、明确的行为变化、实际测试及未验证项。发现与基线不符或真正阻止正确实现的新事实时先核实；不复活旧机制、不顺手展开另一轮平台化改造。

## 5. 保留清单与参考依据

### 不应借本任务删除的边界

| 保留项 | 原因 |
| --- | --- |
| 单一设备 owner、模型线程、真实 pending 句柄 | 实际 SDK/GPU/文件资源所有权；不能通过清空字段或 daemon 化宣称完成 |
| 代际、先置停止事件再等本地锁、实际 SDK 前复查 | 覆盖异步迟到与检查后的撤权；输入过滤不能替代最终提交边界 |
| phase 与 SafetyState | 已撤权仍可能录制收尾，表示不同事实 |
| 来源 freshness、计算提交期限、目标租期 | 分别限制旧观测、过时决策和断流后仍持有的目标；本轮放宽的是采样相位 |
| 首次 finish、staging、完整 schema 与失败段拒绝 | 保护唯一发布、不可覆盖和训练数据真实性 |
| sync / async / RTC、history 窗口 | 是研究功能与模型输入契约；删除属于功能取舍 |
| `ObservationNeeds.union()`、project/build 分工 | 合并 checkpoint 与完整录制需求，保持快照与模型特征计算所有权 |
| HOME 几何与停稳、Ruckig 成功发送后 commit | 分别约束路径与实际已提交参考；不同于可删除的重复时间门槛 |
