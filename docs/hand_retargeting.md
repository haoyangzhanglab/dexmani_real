# XHand 手部重定向

使用 Pinocchio FK、解析雅可比和一次有界 NLopt SLSQP 求解，联合拟合近端/末段方向、骨链位置和有意对指距离。目标是按 XHand 的实际自由度匹配整手姿态。

## 模块与调用链

| 模块 | 职责 |
| --- | --- |
| `teleop/retargeting/landmarks.py` | 掌系、骨长检查、固定骨长标定及 XHand 目标对应 |
| `teleop/retargeting/objective.py` | 位置、方向、对指、阻尼的函数值与解析梯度 |
| `teleop/retargeting/solver.py` | 求解限位、滤波、拒绝原因及提交状态 |

在线入口为 `sensor/vr.py` → `teleop/vr.py::VRController` → `HandRetargeter`。腕部映射与手部拒绝统一通过 `ActionResult` 返回，拒绝原因随本次结果传递。候选求解不推进状态；只有设备提交正常返回后，控制线程才从实际 `RobotCommand` 更新 warm start、阻尼中心、滤波中心和时间戳。每个控制 tick 都重新映射最新有效 landmarks，重复 VR 帧也可在速度限制内继续收敛。每段在停止期间完成录制初值等待及 writer 初始化，writer ready 后等待新的关节反馈，再 prepare streaming 并复核反馈和控制输入。进入 ACTIVE 时建立首次等待期限及录制时长预算；起点检查与参考初始化统一在首次提交前的控制步，会话内骨长标定保留。普通几何退化或已知求解失败在上一有效目标的原期限内重发完整 arm+hand 命令；不续期、不混入失败候选。首目标等待直接以尚无有效提交命令表示；等待期间不发送或录制虚构动作，每次尝试用最新实测关节和 VR 重建未生效参考，等待期限不变。首次提交正常返回后固定本段锚点并播放开始提示。到期、来源过期、取消和真实故障仍结束当前段。

运行入口在构造前检查机器人配置和控制频率。关节反馈的形状及有限性由 XHand SDK 边界保证；HTS 21 点在接收并转换为 FLU 后完成同样检查。reset 仅将 `1e-6 rad` 内的实测边界舍入误差归一，并复制为首次参考，不把求解候选当作实测或已提交命令；求解 seed、候选和提交参考也不共享可变数组。保留 float64 转换、骨长和掌退化检查。

除上述数值舍入量外，实测起点必须位于 `hand.qpos_min_rad/qpos_max_rad` 内；超出时在发送任何本段目标前列出关节、实测值及要求范围，只拒绝本段，健康会话可就位后再次 B。默认 distal 操作下限为拇指 10°、其余手指 5°。默认显式 HOME 目标的 ±5° 到位区间处于操作范围内。自定义范围或 HOME 后，须相应留出到位余量；HOME 报到位并不豁免开始时的实际范围检查。不自动入域、HOME 或清零。

腕部原始四元数在 SDK 基变换前检查并归一化，零范数或非有限姿态被拒绝。接收边界的坏帧不发布，控制侧继续按原来源时间检查观测时效。

每段首次结束时记录一条简短原因日志；求解拒绝包含具体原因，异常保留原 traceback。普通 teleop 不因计算跨过名义 tick 而丢弃有效目标，不补发积压 tick；提交前检查停止和来源年龄。正常控制步不逐帧保存诊断，重复 VR 帧仍运行当次求解。Raw 保存观测、控制及各来源时间；动作截止时间和正常返回时刻 `submit_end_ns` 用于运行期控制，不另行归档。

等待 arm 邮箱锁时耗尽命令期限，同样抛出 `OperationCancelled`，保留原邮箱目标并结束当前段。正常保存/丢弃提示以最终收尾请求的结束原因为准；取消或故障不播放正常完成提示，异常详情只用于诊断。

VR 建立锚点时，实测 FK 必须属于名义工作空间（只允许 `1e-9 m` 计算舍入）；否则拒绝本段，不通过裁剪自动移动到边界。jog 获取新参考时使用 `workspace_with_tolerance` 的端点验收范围；内缩 margin 只限制新目标，每轴裁剪范围包含当前参考点。因此 `z=0.496 m` 可在松键清除参考后再次向内退回，向外输入不扩大越界，纯旋转及未输入平移的轴保持原位置。超出端点验收范围仍拒绝并减速保持。B 重开段重新获取实测锚点，策略 EEF 投影行为不变。

IK 每个局部初值最多 50 次 CLIK 迭代。接受由候选实际 FK 误差、操作限位和端点约束决定，内部收敛标志不单独否决候选。上一命令/实测双初值及有界零空间探索保留；关节权重用于候选排序，不是 CLIK 内部加权。

## 输入与机构对应

右手输入为米制、HTS 原始 21 点：wrist=0；拇指 CMC/MCP/IP/TIP=1/2/3/4；四指 MCP/PIP/DIP/TIP=5–8、9–12、13–16、17–20。接收端将 Unity 左手 XYZ 转为 FLU `(z,-x,y)`。掌系由 wrist→middle MCP 与 pinky MCP→index MCP 确定：+X 掌侧、+Y 拇指侧、+Z 中指侧，不逐指配准。

启动采集 25 个新鲜且来源时间递增的有效样本，固定 15 段骨长和掌宽的中位数；不要求平手，不从弯曲前缀估计零关节角。有效骨长范围 2–180 mm，`calibration_max_relative_mad` 控制标定样本的统计稳定性，默认要求相对 MAD≤10%。`bone_length_tolerance` 控制运行帧相对标定骨长的偏差，默认须≤35%，异常帧不能用于重定向，也不推进提交参考。两个门限分别要求有限且位于 `(0, 1)`，不要求大小排序。不再保存逐段骨长标定归档或成功锚点详情；仍保存实际使用的 `vr_to_robot_rotation`。

每个候选帧先完成掌系与骨长校验，无效时继续采样；通过后只保留已算出的 16 项测量，最终直接求 median/MAD，不再次准备原始帧。URDF 的中立骨段、掌宽、拇指基点与圆轨迹半径在重定向对象构造时固定，逐帧映射复用这些几何量。

| 手指 | 人体方向 | 机器人骨段 | 限制 |
| --- | --- | --- | --- |
| 拇指 | MCP→IP、IP→TIP | thumb_rota_link1→link2→tip | 三轴不能表达完整人体拇指自由度 |
| 食指 | MCP→PIP、DIP→TIP | index_rota_link1→link2→tip | 约 ±10° 侧摆，没有独立 DIP |
| 中/无名/小指 | MCP→PIP、DIP→TIP | 对应 link1→link2→tip | 两轴屈曲，没有侧摆和独立 DIP |

四指位置目标使用固定 MCP 基点及骨长比例，合并人手 PIP→DIP→TIP；方向目标独立保留原始 DIP→TIP。两者不一定能同时满足，不能把人体 DIP 硬映射到不存在的关节。拇指 MCP 目标按掌骨 XY 方位投影到 URDF 的固定高度圆轨迹；投影退化时关闭不可观测的位置项，仍保留指骨方向与对指目标。

重定向、数据导出和策略观测共用组合 URDF 的手部子树。SDK/URDF 顺序按关节名对应，雅可比在堆叠后统一转换为 SDK 列顺序；运行限位由 `hand.qpos_min_rad/qpos_max_rad` 指定，并检查其包含于 URDF 限位。目标映射复用骨段长度进行标定容差检查和方向归一化。

## 目标、参数与运行约束

位置残差按固定 0.10 m 归一化，使用 0.02 m 阈值的径向 Huber；归一化尺度不作为配置项，以免与骨链、指尖及捏合权重重复调节目标强度。方向使用 `Huber(u_robot-u_human, 0.3)/0.3`，阈值约对应 17.3°。方向梯度包含完整归一化导数 `(I-uuᵀ)J/length`。阻尼系数为 `damping_s/dt`。

| 参数 | 当前值 |
| --- | ---: |
| shape / tip 权重 | 0.25 / 2.0 |
| proximal_direction / direction 权重 | 2.0 / 1.0 |
| direction_huber_delta | 0.3 |
| pinch 权重 | 8.0 |
| pinch 开始 / 完全激活距离 | 30 / 15 mm |
| damping_s / smoothing_tau_s | 0.002 / 0.02 s |
| 最终命令变化率上限 | 4 rad/s |
| 求解预算 | 50 次 / 25 ms |

次数预算限制求解工作量，时间预算限制计算耗时。算法内部数值常量 `LOSS_TOLERANCE=1e-7` 只用于 NLopt 绝对目标收敛容差。删除额外的 seed/final FK 回算与改善门槛，读取优化器返回的最优值检查有限性。MAXEVAL/MAXTIME 返回的有效有界候选可接受；只有显式的 `HandGeometryRejected` 和 `RoundoffLimited` 是普通拒绝；一般 ValueError/RuntimeError、非成功返回状态、坏维度、非有限或越界优化结果均保留异常，终止当前段。阻尼在优化中惩罚相对已提交命令的位移，EMA 在求解后平滑输出，两者作用不同。

捏合是辅助目标：掌宽归一化距离门控乘以末段夹角 60→90° 的门控，使用观察到的缩放距离，不强制固定间隙，也不削弱姿态项。它只是几何意图代理，数据中没有接触或意图真值。

求解变量是滤波前候选。最终命令为 `reference + alpha*(candidate-reference)`，`alpha=-expm1(-dt/tau)`；`tau=0` 时 `alpha=1`。`dt` 来自本次控制计算开始与上次 `send_action` 正常返回时刻 `submit_end_ns` 的 monotonic 时间差，不使用 VR 来源帧间隔。首次参考来自范围内的真实姿态及其观测时刻；时间相等直接返回该参考，不获得名义周期的运动额度，时间倒退明确报错。例如间隔 10 ms、上限 4 rad/s 时，最终 `RobotCommand` 每轴相对真实起点最多变化 0.04 rad。失败候选、取消或提交抛错（包括部分设备已提交）不推进参考。普通保持真实重发旧命令且正常返回时，关节和 EEF 值不变，手部参考时间更新为本次返回时刻，避免恢复时累积运动额度。搜索步长除以 alpha，保证滤波不额外压低最终变化率上限。返回前仅裁剪浮点舍入误差；后续 mapper 使用相同操作范围，不会再引入预弯跳变。发送时仍检查机械范围和反馈时效，hand SDK 发送前还须复核同一命令期限；arm 已发布而 hand 发送前到期会取消并停止，录制保留本次提交尝试，但不推进参考。SDK 调用开始后跨期限不追溯否定发送；`commit` 消费提交尝试正常返回的不可变命令。

该约束限制提交尝试目标序列的变化速率。单控制线程中，上次返回时刻不晚于本次计算起点，因此按这个差值分配额度相对于两次实际提交间隔更保守。偶发写 CRC 仍完成本次提交尝试并推进参考，下一周期发送最新绝对目标；连续 5 次写 CRC 或真实 SDK 故障抛错，结束本段且不推进该次参考。提交尝试正常返回不表示物理到位、设备执行 ACK 或实测电机速度满足同一上限。

## 验证边界与限制

XHand 无法独立表达人体 DIP 屈曲及中/无名/小指侧摆，拇指也只有三个驱动轴。方向与位置目标可能无法同时满足；指尖接近不能证明整手姿态一致。强屈曲和部分拇指对掌姿态仍需进一步验证，离线求解结果不代表机器人已经执行或达到目标，当前实现尚未经真机验收。

实现参考 [Sharpa](https://github.com/sharpa-robotics/sharpa-vision-retargeting-sdk/blob/73ac80e980b980b11d8853b874f8efea79095add/supplements/teleop_hand.py) 的固定形态思想及 [Wuji](https://github.com/wuji-technology/wuji-retargeting/blob/531f6ed4250b475d2e9231f54e988fc9b1c5b4ea/wuji_retargeting/opt/adaptive_analytical.py) 的形态/方向联合拟合，没有照搬高自由度手对应或增加通用优化框架。

### 零权重对指项跳过核对

以 `49cca2b` 的原目标函数为临时基线，唯一修改是在构造时判断最终 `pinch_weights` 是否全零，并在回调中跳过该零项；任意非零权重仍用原公式，不设置近零阈值。保留此优化：真实混合片段的收益在重复测量中稳定，非零组的小幅开销未抵消整体节省。基线及计时脚本仅留在仓库外。

只读使用上述五段的 landmarks、观测时间、首姿和历史标定，不解码视频或点云。两方案独立推进参考，保留默认 50 次评估和 25 ms 预算，以相同 `observation_ns` 驱动计算及离散提交；实际间隔为 51.64–70.57 ms，不以运行耗时决定 dt。165909、173916、174250 的历史首姿越限，算法比较共同使用当前合法 HOME，另外两段使用实测首姿，未裁剪原数据。1,880 行中 1,521 行对指权重全零（80.90%），359 行非零（19.10%）；其中五个首行 dt=0、不调用优化器，只参与整段计时。剔除首行后，1,875 次求解中对指权重全零为 1,516 次（80.85%），非零为 359 次（19.15%）。
