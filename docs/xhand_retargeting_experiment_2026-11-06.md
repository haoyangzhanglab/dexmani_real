## 1. Review 结论与范围

本记录整理初次重设计完成的代码测试和 `pnp_apple_banana` 离线实验，供 review 分析使用。记录整理时核对了逐帧输出和八轮计时文件，当时没有重新运行优化实验或单元测试；后续清理复核结果见本节及第 7 节。

**结论：新实现消除了目标段缩短和固定基座手指的不可表达侧摆；在共同的 XHand 映射目标下，五段整体指尖位置、方向及四组距离误差均改善。未完成真机验收，不能据此宣称实际接触或操作性能改善。**

需要同时审阅的限制：

- 投影与定长只保证机构几何一致，不保证整链在关节限位内可达。Thumb 目标仍有显著限位冲突。
- 小指平均指尖误差在五段均小幅增大；部分近端方向 P95、部分指对全帧平均距离误差增大。
- Thumb 对未投影人体末节方向的平均误差在五段均增大，说明机构适配和人体姿态保真之间存在取舍。
- 无名指、小指没有满足共同 activation>0.1 的对指样本；无法据此验收它们的激活对指效果。
- 三段从合法 HOME 重放，属于替代初始条件的手部算法实验；174250 历史记录为 hardware_fault。

后续清理将关节映射改为从 Frame 的 URDF 父关节链提取，补充数组接口说明，合并运行文档的重复内容。清理后用原协议重放五段共 1,880 行，命令、求值次数和拒绝原因均与此前 candidate 逐元素相同；结果另存为 `cleanup_<episode>.npz`。下文八轮性能表仍是原实验测量，不冒称清理后重新进行了八轮基准。

### 2.1 目标构造

数据流：`HTS 21 点 → Palm Frame → 15 骨段/掌宽检查 → XHand 基部与平面适配 → Position/Direction/Pinch/Temporal IK → EMA → 正常提交后 commit`。

- Thumb：CMC→MCP 估计基部角；MCP→IP、IP→TIP 映射两个屈曲段。绕 URDF 轴心旋转第一目标及平面法向。
- Index：MCP→PIP 估计有限侧摆，按 URDF 基部限位截断；第一 Frame 参与 shape 损失。
- Middle/Ring/Pinky：使用 URDF 固定基座与各自平面，去掉不可表达的侧向分量。
- 非拇指远端：`v = l_cal(PIP-DIP)·u(PIP-DIP) + l_cal(DIP-TIP)·u(DIP-TIP)`；投影、单位化后乘以 URDF 固定远段长度。
- 末端方向目标仍使用投影后的 DIP→TIP，因此允许与合成远段位置存在有限折中。
- Pinch：四组目标距离直接取映射后指尖距离；沿用 30→15 mm smoothstep，删除 60–90° 角度门控，不压缩目标间隙。
- 投影退化明确抛出 HandGeometryRejected，不使用任意方向占位。

损失仍为 `L_position + L_direction + L_pinch + L_temporal`。位置 Huber 阈值 0.02 m、归一化尺度 0.10 m；方向 Huber 阈值 0.3；shape/tip 权重 0.25/2，近端/末端方向权重 2/1，Pinch 权重 8，时间阻尼 0.002/dt。SLSQP 最多配置 50 次评估/25 ms，EMA τ=0.02 s，最终命令变化率上限 4 rad/s。

## 4. 指标定义与统计口径

| 指标 | 定义 |
| --- | --- |
| Tip 位置误差 | 最终 EMA 命令的 FK tip 到共同映射 tip 目标的欧氏距离，mm |
| 近端/末端方向误差 | FK 段单位方向与共同投影目标单位方向的夹角，度 |
| 未投影方向误差 | 同一 FK 段方向与 Palm Frame 中原始人体骨段单位方向的夹角，度 |
| Pair 距离误差 | 四组机器人 thumb–finger tip 距离与共同映射目标距离的绝对差，mm |
| 激活子集 | 共同映射目标的 smoothstep activation>0.1；双方使用完全相同的帧掩码 |
| 限位行比例 | 任意命令关节距离操作上下界 ≤1e-6 rad 的行数/总行数 |
| 命令变化率 | 相邻模拟提交命令差绝对值除以 control_ns 差；不代表电机实测速率 |
| 耗时 | 完整 retarget 调用墙钟耗时；不含读盘、初始化、指标计算和 commit |

两种算法都对同一套任务书映射目标评分，而不是比较各自目标函数值。但这套共同目标由 candidate 的目标构造实现生成，**不是独立人工标注、接触真值或机器人执行真值**。几何不变量测试用于核对其正确性，未投影方向误差用于暴露映射取舍；不能仅凭拟合该目标更好就推断人体姿态保真全面更好。

误差包含五个初始化行；计时和求值次数剔除五个 dt=0 行。下文“总体方向”混合五指的近端/末端共十个方向。逐段总体统计将对应帧和指/指对展平后计算，P95 不是逐指 P95 的平均。

计时先做过完整 baseline/candidate 初次重放，再由 benchmark.py 交替顺序运行八轮，每轮每方案启动独立进程。脚本没有在每个子进程内另加不计时的完整预热；因此不要称为严格的进程内稳态基准。表中为每轮 P50/P95 再分别取八轮中位，没有置信区间或显著性检验。25 ms 是求解器预算，实测 retarget P95 不是最坏实时延迟保证。
