项目真正需要什么

当前任务为 xArm7 + 12 自由度 XHand；本次 ManiFlow 使用两帧 joint_state/point_cloud，H=16、P=H−N+1=15、A=8，16 Hz，NFE=4，推理约 26–38 ms。项目同时保留 joint 19 维与 EEF 21 维动作，以及后续逐指几何/触觉交互策略。因此需要明确的模态、单位、顺序、观测时间与动作时间；不需要为了这个本地快速策略重建多机器人插件体系、分布式 VLA 服务或通用任务状态机。

已有“一个设备 I/O owner + 一个串行模型 worker”的边界合理：推理不直接操作设备，停止/新 episode 不接收旧 query。应保留该结构，并让普通 chunk 执行路径容易读懂。研究触觉融合时，运行时自动加入抓取判定、松手或重抓，会改变所评估的系统；这些只能作为独立的研究条件。

真正可以简化的约束

  1. 普通 async 不必继承严格固定交接的所有限制。runner.py:736–766 同时要求正确 handoff_slot、结果就绪、completed_ns 不超过 slot 的名义开始时刻。假设结果在名义时刻后 2 ms 完成，而本拍传感器读取在约 12 ms 后才结束，它已可用于本拍下发，但当前检查仍拒绝。对普通 async，更合理的条件是实际消费索引、结果是否可用、源年龄及剩余有效预测。这个例子是代码条件分析，本次 sync 记录没有触发它。
  2. RTC 的前缀约束要留在 RTC 路径。已承诺执行的物理动作必须与生成时的条件一致，尤其 EEF 经 IK/投影后不能再拿未实现的原始动作当条件。可以隔离这部分代码，但不能仅为了简化删除其语义保护。当前 ManiFlow adapter 只支持普通 sync/async，RTC 仅实现了 DDIM 路径，这是如实拒绝不支持功能，不是应放宽的检查。
  3. 静态检查集中在加载，动态检查集中在实际边界。维度、字段、归一化、动作表示和配置范围加载时检查；进入模型前检查所需观测；进入 SDK 前检查授权、设备状态、物理范围和时效。可以合并对同一不可变数组的内部重复检查，但时间和授权会在推理/SDK 调用期间变化，不能一并删掉。
  4. 性能 warmup 与语义准入分开说明。shape/单位/normalizer 不匹配必须失败。warmup 的耗时是运行参数选择的证据，不是未来延迟的保证。若继续采用硬交接协议，预算检查仍需满足；要容纳抖动，应先定义实际索引与过期处理，不能只删除预算校验。
  5. 全模态完整性只表达全模态实验集的要求。当前 AGENTS 明确要求公共导出全部 13 字段完整，本轮遵守。它对公平比较视觉/触觉策略有价值，不能自动叫作多余。但它不代表一段 Raw 损坏，也不代表缺失辅助量必然影响只消费 joint_state/point_cloud 的模型。是否另设训练准入属于明确的数据研究设计，不应暗中修改。

并非所有“重复检查”都多余。run_id/停止后废弃旧推理、SDK 前最终硬限位、缺测保留 NaN、相机与点云的来源对应，以及 writer 失败保留 staging，都对应真实设备或数据边界。LeRobot 的异步实现同样保留 reset epoch 和前缀/消费延迟检查。

本地证据：执行配置与 warmup、所需输入检查、SDK 边界、全模态导出。参考：LeRobot RTC reset 与延迟处理。

“简洁、正确、好用”对应的最小实现方向

保留现有模型接口 obs_history → future_actions[P,D]，保留 checkpoint 中的数值表示与 dt。设备侧仅负责观测、一个当前动作块、至多一个待完成推理、目标实现与下发。普通 sync 用于清晰的基线/诊断；普通单请求预取用于本次低延迟连续执行；RTC 只在确有研究需求且解码器支持时启用。不要新增一套调度 registry、兼容层或抓取任务框架。

异步最关键的正确性是：新块按生成它的观测时刻和已消费步数选取动作，不能等它到达后无条件从第 0 步重新播放。若没有仍有效的动作窗口，应明确结束并保留证据；若研究允许等待/保持，也须显式定义其时间与动作语义，不能无限重复最后动作或补造成功执行。

好用体现在入口直接给出“模型/动作表示、NFE、dt、A、是否预取”这几个影响实验的选择，停止原因区分策略任务失败、计划耗尽/时序异常、设备故障与记录故障。操作者不应为不使用 RTC 的策略理解冻结前缀和 guidance 参数。
