修改前审计记录

判断：当前下发路径仍有明显可减的复杂度，集中在重复校验、分散的异常与停止处理、采集时序要求进入运动停止条件、普通发送隐含模式恢复。目标是明确现有函数的唯一职责，直接删除重复代码。参考项目的整个仓库未必更小；应比较相同功能下的执行路径，而不能把它们隐藏在底层服务、SDK 或推理线程中的必要职责算成“没有”。

2．当前路径与可删除项

遥操作：TeleopRunner → execute_control_step → TeleopController → ActionRealizer/IK → RobotCommand → DexManiRobot._send → driver → SDK。eval：PolicyRunner → action intent → ActionRealizer → RobotCommand → 同一 _send → driver → SDK。这些名字不都代表多余层：VR 映射、IK、模型推理与 SDK 是真实边界；问题在于多个函数同时负责验证、结束控制和解释失败。

位置／问题判断具体删减方向
相同目标的 shape、finite 和物理限位realize、projection、joint_target_rejection、_send、driver 多次处理同一向量。操作限位与物理限位有不同用途，但 _send 与 xArm7.servo 的物理检查完全重复。配置合法性留在启动；外部输入在进入动作实现时检查；最终物理目标在设备边界统一检查。先删 xArm driver 重复项。XHand 另有独立示例与 stop/hold 调用，统一其调用边界后再删，保留双设备发送前整体验证，不引入“已验证令牌”或绕过标志。
EEF eval 重复检查 IK 解IK 已按同一 current、previous、hand target 检查跳变、操作限位、自碰撞；ActionRealizer 随后再运行同样检查。最终 FK 工作空间与环境碰撞不属于这个重复集合。删除普通 EEF eval 的重复动态／自碰撞检查，保留 IK 未承担的最终工作空间与环境检查。joint 模式没有经过 IK，仍需对应几何检查；RTC 冻结命令稍后执行，其新反馈检查不能一并删。
健康检查重复进入权限判断_authorized 调用 robot.check，后者扫描 supervisor 子进程。双设备发送前后重复执行；PolicyRunner.step 在判断本拍是否到时之前也检查，出现在 1 ms 轮询中。服务健康检查移至控制周期或既有空闲检查；SDK 前仅看本地停止标志、run_id 和当前有效期。不要增加 watchdog。此项会改变服务故障的检测时机，需要明确周期并复核。
普通发送隐含恢复 Mode 6_send 在 arm_stopped 时调用 prepare_streaming，把设备模式切换、检查和时间开销带入当拍。eval 已在开始阶段准备模式，teleop 等入口仍依赖隐式路径。统一在开始／恢复阶段显式准备设备，再授予运动；删除 _send 内的模式恢复分支。同步覆盖 teleop、replay、键盘控制和标定入口，不增加另一层兼容调用。
多层停止与失败分类teleop execute_control_step 为 93 行，eval _execute_slot 为 85 行，_send 为 78 行；这些是函数物理行数，不是性能指标。多处同时记录、撤权、停止、区分异常、再包装异常。SDK owner 只返回下发结果或携带部分结果的错误；每个 runner 统一完成一次撤权、停止和录制收尾。可删除 teleop 的独立单步包装与可推导结果字段；复用现有 robot.send_action，不新建通用 Executor。
eval 决策年龄重复判定模型回收、交接、step、execute 均可能以不同原因结束同一轮，最终下发还会重新计算有效期。检查发生时刻不同，不能机械删掉所有重复名字。观测入口检查来源，查询保留 run_id，执行前汇总一次当前动作截止时间，传给每次 SDK 调用。删除没有新输入或阻塞操作介入的重复判定与结束原因分支；保留每次 SDK 前的最后检查。
录制开关影响控制失败语义启用 recorder 时首次无目标就结束；不录制时允许连续 10 次失败，期间可能仍追向上一端点。调试与采集运行的是不同控制系统。删除 _DEBUG_FAILURE_LIMIT 和计数维护，统一无可执行目标时的停止行为。录制开关只控制产物；writer 真正出错仍结束 capture 并保留已采前缀。
遥操作 dt/4 采样准入固定采样偏差要求直接进入运动停止路径，并且未录制时也生效。它比“当前反馈是否新鲜”更严格。优先移除未录制路径上的数据采样准入。采集路径将数据时序判定归还导出，Raw 保留真实时间；不伪造时间、不补动作。导出当前仍可能拒绝整段，不能借此暗中放宽训练时间语义。实际过期、失联与整拍错过须单独处理。

源码入口（现已更新）：ActionRealizer、Robot owner、xArm driver、XHand driver、teleop 动作映射、teleop runner、policy runner、supervisor。

4．保持的最小职责

  • 动作生成：VR 映射／retarget／IK，或策略动作选择；各自完成必要转换，不改变策略时间和动作定义。
  • 设备下发：双设备目标预检查、每次 SDK 前的停止／run_id／有效期检查、每个设备一次调用及原始返回码。
  • 会话收尾：一处撤权和停止，记录实际尝试及部分结果，保存 Raw 前缀与结束原因。

保留的具体状态包括：一个 epoch 防止旧推理结果执行；arm/hand 分别的 dispatch 状态，因为顺序 SDK 调用可能只成功一半；停止失败后禁止新运动；只在 HOME 检查到位。正常下发仍不增加动作后读回确认、不等待到位、不重发普通动作。

不能只检查一次权限后无条件连续发两个设备：操作者可能在 arm SDK 阻塞期间按停止，第二次检查应阻止 hand 继续发送。这与同一不可变目标反复检查有限性不是同一种重复。

5．实施顺序与判断边界

  1. 先处理等价删减：完全重复的物理检查、EEF 已完成的重复检查、teleop 单步包装和失败归因重复。保留现有 SDK 调用顺序与 Raw 语义，用假 SDK 复核双设备部分下发、停止介入及记录错误。
  2. 再统一生命周期：将模式准备移到开始阶段；统一录制／非录制的失败行为；将服务检查从高频推理轮询中移出。避免新状态机、通用执行器或多个兼容入口。
  3. 最后调整时序停止规则：先去掉未录制遥操作的 dt/4 准入，再处理采集与导出的职责分离；通过实际时间记录确认数据可用性。保留 async/RTC 索引对齐、过期动作拒绝和必要来源新鲜度。

上述机制主要影响维护成本、运行一致性和主动停止概率。此前统计中的验证与解码耗时很小，不能把这些删减当作百毫秒跟随滞后的已证实解法。xArm 物理跟随仍按固定轨迹的模式／频率对照处理；无须先添加平滑、预测补偿或高频控制框架。完整停止、Raw 不变性、真实异常记录与模型线程有序关闭不因参考代码较短而删除。
